## 2. 왜 지금 하나 — 그리고 무엇을 기대하지 말아야 하나

**하는 이유는 정확성이다.** SEO 회수는 기대하지 마라. 2026-08-05 28일 GSC 기준 번역본 노출은
`de` 278 · `ja` 40 · `id` 20 · `es` 19 · 나머지 13 이하이고 **클릭은 전 언어 합쳐 2**다.
85편을 고쳐도 노출·클릭은 거의 안 움직인다. 그래도 고치는 이유는 하나다 —
**틀린 계산이 20개 언어로 배포돼 있고, 우리가 그걸 알고 있다.**

⚠ 이 문서를 근거로 «다국어 경화하면 트래픽이 오른다»고 기대하지 말 것. 그 기대는 데이터가 부정한다.

## 4. 방법 — «재번역»이 아니라 «패치»다

번역은 원래 직역이 아니라 현지 맥락 재저작이다([[translation-is-contextual-reposting]]).
**하지만 이번 작업은 재저작이 아니다.** 고쳐야 하는 것은 §13 불변 항목 —
**숫자·계산·룰**뿐이고, 이것들은 언어가 바뀌어도 값이 같다.

```
1. EN 마스터의 해당 커밋 diff를 연다 (ec11984 · 992982d · 3db7238 · 973144b)
2. «값이 바뀐 자리»만 뽑는다 (19.6→19.1 · 407→408 · $25→$24 · two seats→one seat …)
3. 각 언어 파일에서 그 값을 grep한다
   ★축약형·현지 숫자표기도 함께 검색할 것 — 과거에 en의 $85.6M·ja의 8,560万ドル를 놓쳤다
     (update-calendar.md 8/5 항목의 교훈)
4. 값만 교체한다. 문장·훅·H2는 건드리지 않는다 (현지 재저작분을 훼손하지 말 것)
5. masterUpdated 를 EN updated 값으로 갱신 + updated 를 작업일로 갱신
```

🔴 **하지 말 것**
- 전문 재번역 (현지화 자산이 날아간다)
- PowerShell 일괄 치환 (CLAUDE.md §16 — 한글·다국어 파일이 깨진다. Node `readFileSync(p,'utf8')`)
- KO를 기준으로 번역이 맞는지 따지기 (REVIEW-PROTOCOL §1 — 내용은 달라도 된다)
