# 홀덤마스터 UI·UX 직접 방문 점검 — 2026-09-15

## 결론

크림·포레스트 그린·골드의 브랜드 방향은 유지할 가치가 있다. 우선순위는 **깨진 이동 경로 → 문제 전환·입력값 보존 → 모바일 탐색과 가독성**이다. 아래는 개선 제안이며 사이트 코드를 수정하거나 배포하지 않았다.

## 확인 범위와 방법

라이브 `https://www.holdemmaster.com`을 Playwright Chromium으로 방문해 캡처와 DOM을 확인하고 실제 버튼·입력을 조작했다. 별도 에이전트가 도구 기능을 재현하고 공통 UI 코드를 독립 검토했다.

| 대상 | 실제 확인 |
|---|---|
| 홈 `/`, `/community` | 390×844·1440×900, 전체/커뮤니티 필터, 채팅·이벤트·프로필 탭, 인기글 이동 |
| `/blog` | 양쪽 폭, 검색 제출·검색 결과 없음·필터 해제·카테고리 선택과 새로고침 |
| `/blog/holdem-tiebreak-rules` | 양쪽 폭, 모바일 목차 열기와 해당 절 이동, 읽는 중 고정 바 동작 |
| `/tournaments` | 양쪽 폭, 국내 필터, 목록 순서·현재 상태·글자 색상 |
| `/calculator` | 양쪽 폭, 아웃츠·팟오즈 입력·탭 왕복·임플라이드 펼침·족보 판별 |
| `/hands`, `/quiz` | 양쪽 폭, 족보 표, 퀴즈 응답·다음 문제·10문제 완료·결과·재시작 |
| `/login`, 커뮤니티 게시글 상세 | 모바일, 로그인/회원가입 전환·키보드 포커스·비로그인 댓글 안내 |
| `/solver` 및 솔버 앱 | 랜딩 양쪽 폭, 실행 버튼으로 새 탭 앱 진입·모바일 소개 화면 |

로그인 완료·소셜 인증·글/댓글/채팅 전송·이벤트 참여는 실행하지 않았다. 솔버는 앱 진입까지 확인했고 새 계산은 실행하지 않았다. 포스트의 포커 내용 전체 검수, 전체 다국어, 실기기 Safari, 실사용자 성능 지표는 이번 범위 밖이다.

검수 기준은 `CLAUDE.md`, `REVIEW-PROTOCOL.md`, `docs/DESIGN.md`, 해당 확정 결정 원문, `screen-review` 및 `web-design-guidelines` 스킬이다. [Vercel Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) 최신 원문도 확인했다. 포스트 내용 검수용 hard/build는 소스 변경이 없어 실행하지 않았다.

## 1. 먼저 고칠 기능과 상태 안내

### 1) 홈 인기글의 대회 링크가 404로 연결됨 — P1 · 직접 재현

- **재현:** 데스크톱 홈 → 오른쪽 ‘이번 주 인기글’ → ‘2026 홀덤 대회 일정’ 클릭.
- **실제:** `/post/page:tournaments`로 이동해 ‘찾으시는 페이지가 없습니다’ 화면이 열린다.
- **원인:** `app/community/community-client.tsx:1532`가 `blogSlug`가 없는 항목을 모두 `/post/${id}`로 보낸다. 이 항목은 `pageHref: /tournaments`가 있다(`:496`).
- **개선:** 링크 결정에 `pageHref`를 반영하고 같은 종류의 인기글 목적지도 함께 점검한다.
- **확인 기준:** 같은 클릭으로 `/tournaments`에 도착한다.
- [홈 화면](ui-ux-audit-2026-09-15/home-desktop.png) · [클릭 뒤 404](ui-ux-audit-2026-09-15/popular-tournament-404.png)

### 2) 퀴즈의 다음 문제에서 새 카드가 보이지 않음 — P1 · 직접 재현

- **재현:** `/quiz`에서 응답 → 아래쪽 ‘다음 문제’ 클릭.
- **실제:** 이전 스크롤 위치가 유지돼 새 문제의 보드·홀카드는 위로 벗어나고 선택지 하단이나 푸터가 보인다. 모바일·데스크톱 모두 재현했다.
- **원인:** `app/quiz/quiz-client.tsx:50`의 `next()`는 문제 상태만 바꾼다.
- **개선:** 문제 전환 시 문제 제목으로 스크롤하고 키보드 초점도 옮긴다. 고정 헤더 높이를 반영한다.
- **확인 기준:** 다음 문제마다 제목·카드·선택지 시작 부분이 바로 보인다.

### 3) 계산기 탭을 왕복하면 입력값이 사라짐 — P2 · 직접 재현

- **재현:** ‘팟 오즈’에 팟 9,000·콜 3,000 입력 → 25% 확인 → ‘아웃츠’ → ‘팟 오즈’ 복귀.

- **원인:** `app/calculator/calculator-client.tsx:339`의 탭 내부 상태가 `:1478`의 조건부 렌더링으로 다시 만들어진다.

### 4) 이벤트의 날짜·운영 상태·참여 안내가 서로 다름 — P2 · 화면 및 코드 확인

- **관찰:** 9월 15일 방문인데 홈은 ‘Soon/준비 중’, 이벤트 탭은 ‘2026년 6월 이벤트’, 비로그인 안내는 ‘로그인 후 참여 가능’이다. 현재 열려 있는 이벤트인지 판단하기 어렵다.

### 5) 블로그 카테고리가 새로고침하면 풀림 — P2 · 직접 재현

- **재현:** `/blog` → ‘초보 가이드’ 선택 → 새로고침.
- **실제:** 선택한 카테고리가 ‘전체’로 돌아온다. 검색어는 제출 시 URL에 남지만 카테고리는 남지 않는다.
- **원인:** `app/blog/blog-index-client.tsx:53`, `:68`, `:113`, `:263`의 상태 저장 범위가 다르다.
- **개선:** 검색어·카테고리·태그를 URL과 함께 관리해 새로고침·공유·뒤로가기를 일관되게 한다. 기존 정적 HTML 보존 방식은 유지한다.
- **추가 정적 후보:** 태그로 진입한 뒤 검색을 제출하면 URL에서 태그만 빠지는 경로도 있다. 이 조합은 별도 라이브 재현하지 않았다.

## 2. 탐색 구조와 가독성 개선

### 6) 모바일 홈에 검색·가이드·도구 진입을 노출 — P2 · 개선 제안

- **관찰:** 데스크톱은 왼쪽 레일에서 검색·규칙·계산기 등을 찾을 수 있다. 모바일 홈 첫 화면에는 전체/전략/커뮤니티 필터, 솔버 홍보, 대회 카드가 먼저 나온다. 하단 탭은 커뮤니티 기능 중심이다.
- **영향:** 처음 방문한 학습자가 ‘족보를 배우기’나 ‘계산기 사용’으로 바로 이동하기 어렵다.
- **제안:** 모바일 홈 상단에 검색 진입과 ‘처음 배우기 / 전략 읽기 / 도구 사용’처럼 목적이 분명한 짧은 진입 영역을 둔다. 세부 링크는 공통 메뉴로 묶는다. 위치·문구는 시안으로 비교할 디자인 제안이다.
- **원인 위치:** `app/community/community-client.tsx:1178`의 모바일 전용 구성, `components/side-rail.tsx`, `components/hub-shell.tsx:139`의 다른 허브용 모바일 탭.
- **확정 결정 존중:** 기존 하단 4개 탭을 유지하고 별도 블로그 탭 신설을 제안하지 않는다(`components/bottom-tab-bar.tsx:120`).
- [모바일 홈 첫 화면, 390·seg-01](ui-ux-audit-2026-09-15/home-mobile.png)

### 7) 대회는 진행·예정 일정을 먼저 보여주기 — P2 · 개선 제안

- **관찰:** 상단에는 현재 날짜와 진행·예정 대회 요약이 있지만, 일정 카드 목록은 종료된 1월 대회부터 시작한다. 현재 필터는 전체/국내/해외뿐이다. 국내 선택 후 첫 진행 대회인 제8회 홀덤 마스터스 제목은 문서 약 3,573px 지점에 있었다.
- **영향:** ‘지금 참가할 대회’를 찾으려면 과거 일정부터 지나야 한다. 기본 전체 화면의 문서 높이는 모바일 약 57,805px였다. 이 길이는 탐색 부담의 관찰값이며 로딩 속도나 이탈률의 증거는 아니다.
- **제안:** ‘진행 중 / 예정 / 종료’ 필터와 월 이동을 제공하고 기본값은 진행·예정으로 잡는다. 종료 일정은 아카이브로 계속 접근 가능하게 한다. 상단의 현재 일정 요약을 해당 카드에 연결한다.
- **원인 위치:** `app/tournaments/tournaments-client.tsx:375`, `:430`, `:439`.
- [모바일 일정 첫 부분, 390·overview-1](ui-ux-audit-2026-09-15/tournaments-overview.png) · [국내 필터](ui-ux-audit-2026-09-15/tournaments-domestic.png)

### 8) 검색 중에는 결과를 화면 위로 올리기 — P2 · 개선 제안

- **관찰:** ‘팟 오즈’ 검색 결과 6편이 정상으로 나오지만, 검색 뒤에도 약 242px 높이의 학습 로드맵 배너가 남는다. 390×844 첫 화면에는 결과 개수까지만 보이고 실제 첫 글은 아래에 있다.
- **제안:** 검색·필터 적용 중에는 소개와 로드맵을 짧게 접고 입력창 바로 아래에 결과 수와 글을 배치한다. 기본 목록 화면에서는 로드맵을 유지한다.
- **원인 위치:** `app/blog/blog-index-client.tsx:107`의 `isFiltering`, `:195`부터 로드맵 배너.
- [검색 직후 실제 뷰포트](ui-ux-audit-2026-09-15/blog-search-mobile.png)

### 9) 밝은 배경의 골드 글자 대비 보강 — P2 · 측정 확인

- **관찰:** 대회 H1은 라이브 계산 스타일상 `rgb(185,144,39)`, 배경은 `rgb(244,240,231)`, 글자는 36px·700이다. WCAG 식으로 계산한 대비는 **2.607:1**이다. 큰 글자의 3:1 기준에 못 미친다. 일반 글자 기준은 4.5:1이다. [W3C 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- **제안:** 밝은 배경의 정보성 글자는 더 진한 골드 또는 포레스트 그린으로 두고, 현재 골드는 면·테두리·장식에 활용한다. 다크 표면용 골드와 구분하는 브랜드 규칙은 유지한다.
- **원인 위치:** `app/globals.css:63`, `app/tournaments/tournaments-client.tsx`의 `text-primary` 제목.
- 이 측정은 해당 색 조합에 대한 것이다. 모든 글자·버튼의 대비를 전수 검사한 것으로 확대하지 않는다.
- [대회 화면](ui-ux-audit-2026-09-15/tournaments-overview.png) · [라이브 색상 기록](ui-ux-audit-2026-09-15/colors.json)

### 10) 로그인·계산기의 입력 접근성 보완 — P2 · 라이브 및 코드 확인

- **로그인 재현:** Tab으로 이메일 입력에 도달했지만 포커스 링이 없다. 계산 스타일은 `outline: rgb(185,144,39) none 2px`, `box-shadow: none`이다. 이메일·비밀번호는 placeholder만 있고 고정 라벨이 없다.
- **계산기 재현:** 팟오즈 숫자 입력 2개와 승률 슬라이더는 보이는 설명과 입력이 연결되지 않아 DOM의 `labels`가 빈 배열이다.
- **제안:** 고정 라벨과 `id/htmlFor`, 입력 종류별 자동완성, 명확한 키보드 포커스를 추가한다.
- **코드 위치:** `app/login/page.tsx:184`, `:193`, `:202`; `app/calculator/calculator-client.tsx:358`, `:366`, `:388`.
- **추가 개선:** 로그인 화면에 비밀번호 재설정 진입이 없다. 로그인 성공 후 복귀도 현재 코드는 `/`로 고정이다(`app/login/page.tsx:50`, `:95`). 원래 채팅 탭·페이지로 돌아가도록 `next`를 연결할 필요가 있다. 실제 로그인 완료 경로는 실행하지 않았으므로 이 부분은 정적 판단이다.
- [키보드 이메일 포커스 화면](ui-ux-audit-2026-09-15/login-focus.png)

### 11) 모바일 족보 표의 설명을 별도 줄로 배치 — P3 · 개선 제안

- **관찰:** `/hands`의 4열 표에서 순위가 ‘1 / 위’로 갈리고 설명이 좁은 열에서 자주 끊긴다. 표 높이는 약 907px였다. 데스크톱에서는 같은 문제가 두드러지지 않는다.
- **제안:** 모바일은 ‘순위·족보·확률’을 한 줄에, 설명과 예시를 다음 줄이나 펼침 영역에 둔다. 데스크톱 표는 유지한다.
- **코드 위치:** `app/hands/hands-client.tsx:70`, `:88`, `:91`.
- [모바일 표 실제 화면](ui-ux-audit-2026-09-15/hands-table-mobile.png)

## 3. 추가 관찰과 검증 경계

- **홈 대회 티저 문구도 갱신 필요:** 홈의 `/tournaments` 소개에는 이미 지난 8/3~5·8/7·9/3 일정이 ‘예정’으로 남아 있다(`app/community/community-client.tsx:496`). 대회 화면의 오늘 기준 요약과 같은 데이터에서 생성하면 드리프트를 줄일 수 있다. `docs/update-calendar.md`의 9/14 APPT 종료 항목은 기존 대기 건이며, 이번에 결과 기사까지 검수·수정하지 않았다.
- **채팅 잠재 결함, 라이브 조건 미검증:** 초기 조회가 오름차순 후 50개 제한(`app/community/chat-tab.tsx:181`)이라 대화가 50개를 넘으면 최신 메시지가 빠질 수 있다. 현재 열어 본 방은 적은 메시지만 있어 그 상황을 재현하지 않았다.
- **로그인 내부 모달, 정적 후보:** 글쓰기 모달의 초점 이동·제한·Escape 복귀 처리가 없다(`app/community/community-client.tsx:1132`). 로그인 상태에서의 실사용 확인이 후속 조건이다.
- **모바일 글 목차는 정상 동작:** 처음 진입 시 상단 도구 바를 숨기는 구현 의도를 원문에서 확인했다. 스크롤 후 목차를 열어 ‘키커란 정확히 무엇인가?’로 이동했고 헤더 아래에 해당 제목이 보였다. 초기 숨김 자체를 기능 고장으로 집계하지 않았다.
- **관찰된 이미지:** 본문 요약 박스·학습 맵·목차는 읽기 흐름에 도움이 됐다. 홈·목록은 큰 썸네일과 긴 카드가 반복되므로 이후 시안에서는 추천 카드 아래를 작은 이미지의 목록형으로 비교해 볼 수 있다. 이 제안의 전환·이탈 개선 효과를 실측한 것은 아니다.

## 4. 정상 작동 확인

- 기본 배치의 8경로 × 2폭, 도구 배치의 퀴즈 포함 3경로 × 2폭에서 문서 가로 넘침과 콘솔 오류는 없었다. 일부 분석 수집 및 선행 로드 취소 요청은 페이지 고장으로 집계하지 않았다. 커뮤니티 게시글 직접 진입은 정상 확인했다.
- 블로그 검색·검색 결과 없음·필터 해제와 모바일 목차 이동은 작동했다.
- 팟오즈 `3,000 ÷ (9,000 + 3,000) = 25%` 즉시 계산이 맞았다. 아웃츠 9개는 플랍 이후 약 35%, 턴 이후 19.6%를 표시했다. 족보 판별은 `A♠ K♠ Q♠ J♠ 10♠`를 로열 플러시로 표시했다.
- 모바일·데스크톱 퀴즈 각각 10문제를 진행해 피드백·결과·재시작을 확인했다. 전체 문제 생성기의 정확성 보증은 아니다.
- 솔버 랜딩 실행 버튼은 실제 앱을 새 탭으로 열었고 모바일 소개 화면에 예제·트레이너 진입이 보였다. [앱 진입 화면](ui-ux-audit-2026-09-15/solver-app-mobile.png)

## 실행 순서 제안

1. **작동 흐름:** 인기글 404 → 퀴즈 문제 전환 → 계산기 값 보존 → 검색 필터 보존.
2. **신뢰·접근성:** 이벤트 안내 일치 → 홈 대회 티저 → 입력 라벨·포커스 → 글자 대비.
3. **화면 구성:** 모바일 홈 진입 → 대회 진행·예정 우선 → 검색 결과 배치 → 모바일 족보 표.

미래 수정 시 위 재현을 같은 폭으로 반복해 전후를 비교한다. 디자인 제안은 현재 승인된 브랜드와 하단 탭 결정을 지키는 시안으로 구체화한다.
