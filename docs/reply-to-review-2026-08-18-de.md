## 2. ✅ G2 — 디렉티브 마커 누수 (커밋 `8002c216`)

### 지시서의 2.7배였고, **원인이 셋이었다**

`:::pull` 블록형 미렌더는 **27곳·9로케일**(de 5 · 나머지 8로케일 각 3)이었고 **KO
`holdem-implied-odds`**가 포함돼 있었다 — 한국어 독자가 본문에서 이걸 그대로 보고 있었다:

```

필요 추가 수익 = (콜 금액 ÷ 에퀴티) − (현재 팟 + 콜 금액)
:::
```

그리고 **그걸 고치고 산출물을 훑자 같은 결함군이 두 겹 더 나왔다.**

| # | 원인 | 규모 |
|---|---|---|
| ① | **블록형 미지원** — `pull`·`note` 만 한 줄형만 처리. 다른 블록 디렉티브(stripe·steps·compare·card·readnext)는 전부 같은 관용구를 쓰는데 이 둘만 빠져 있었다 | pull 27 + **note 31곳·8로케일** |
| ② | **본문 캡처가 `[^\]]+`** — 「본문에 `]` 가 없다」는 가정을 **마크다운 링크가 깬다** | tip·note 등 |
| ③ | 🔴 **순서** — ②만으로는 안 닫혔다. 링크 변환이 디렉티브의 **여는 `[` 를 링크의 `[` 로 먹어** `:::note[…]:::` 을 `:::note<a …>…</a>.]:::` 로 만들고 있었다 | 4페이지 |

→ 프로즈 디렉티브 4종(kicker·pull·note·tip)을 **링크 변환 앞으로 옮겼다.** 코드에 「순서를
내리지 마라」를 근거와 함께 박았다.

### 🆕 게이트 — `npm run check:directives`

원인이 셋이라 «어느 디렉티브가 깨졌나»를 세는 방식으로는 안 닫힌다. 그래서 **원인이 아니라 증상**

🪶 **「마커가 없다」와 「렌더됐다」는 다르다** — 삼켜졌을 수 있어 개수로도 대조했다:

## 3. ✅ W5~W10 — 에퀴티 실현율 (커밋 `6e9c734f`)

### 지시서 판정에 **동의한다.** 직접 검산으로 재확인했다

헤즈업 팟 EV 합 = 팟 →  `e·R_IP + (1−e)·R_OOP = 1`.
e=0.5 이면 `R_IP + R_OOP = 2` → **OOP 85% ⇒ IP 115% · OOP 60% ⇒ IP 140%.**
IP 상단을 100%로 캡한 밴드는 OOP 60–85%와 **공존 불가**다. 지시서가 짚은 대로 **같은 글이 이미
「IP는 체계적으로 초과 실현한다」**고 쓰고 있어 한 글 안에서 표와 본문이 서로를 부정했다.

### 고친 방향 — **없는 수치를 만들지 않았다**

- IP: 「85–100%」 → **「100% 초과」**. OOP<100% 이면 무조건 참이라 새 가정이 필요 없다.
  ⚠ **「115–140%」로 쓰지 않았다** — 그 값은 e=0.5 를 가정해야 나온다.
- OOP: **60–85% 유지**(연구 인용값이고 반박되지 않았다).
- 🔴 **귀속을 갈랐다** — 구판은 IP·OOP를 통째로 「솔버·DB 연구가 시사」에 걸었는데 **IP >100% 는
  연구가 아니라 산수**다. 연구 귀속은 OOP 밴드에만 남겼다.
  **원장 #59(「솔버 출력은 empirische Belege 가 될 수 없다」)와 같은 규율을 적용한 것이다.**
- 각 로케일 정의 블록에 **왜 100%를 넘는지** 한 문장을 넣었다(팟 보존). 안 넣으면 오타로 읽힌다.

**범위: 103곳 · 9로케일** — 로케일당 6자리(tldr·정의블록·표·이미지alt·FAQ·정리), es 7자리(고유
문장 1), **KO 필라 `position-is-everything-in-holdem` 2자리.**
