## 1. 경로

| 방향 | 자리 | 규율 |
|---|---|---|
| 검수장 → 본체 | `~/Downloads/홀덤검수/reports/발신-본체-*.md` + `fix-handoff-*.md` | 🔴 **검수 폴더는 읽기 전용.** 착수 전 `git -C ~/Downloads/홀덤검수 log --oneline -5` |
| 본체 → 검수장 | `docs/reply-to-review-<날짜>.md` | 본체 레포에 쓴다 |
| 솔버 → 본체 | `~/Downloads/클로드-프로그램만들기/handoff-to-main-site/` | 「배포 완료」 통보 시에만 번들 해시로 확인(§4) |
| 본체 → 솔버 | `docs/reply-to-solver-<날짜>.md` | 본체 레포에 쓴다 |

- **우편함 큐는 `홀덤검수/mailbox/MAILBOX.md` 하나다.** 세션 시작 시 `🔴` 검색 → 자기 앞 행 갱신(`mailbox:` 커밋).
- 🟢 사람이 메시지를 옮길 필요 없다 — 두 세션이 같은 디스크를 본다. 사장님이 할 일은 세션 시작 하나.
- 🔴 **검수 세션은 자동으로 우편함을 읽지 않는다** — 사장님이 「HANDOFF 보고 시작해」로 시킨다.
  (그쪽 `CLAUDE.md` 신설은 **사장님이 「내가 시킬게」로 정하셨다 — 만들지 마라.**)

## 2. 발신 규율

- 🔴 **발신 전 `git pull` 하고 마지막 메시지 ID를 다시 봐라** — 08-18에 ID 충돌이 두 번 났다.
  충돌 시 나중에 커밋한 쪽이 내린다.
- 이미 발신한 통지는 **다시 보내지 마라** — 회신 대기 상태는 핸드오프 미결 절이 관리한다.

## 3. 수신·이행 규율

- 🔴 **지시서와 «영향 범위»가 다른 일이 세 회차 연속 있었고 셋 다 KO 본사이트가 포함됐다.**
  → 지시서를 받으면 **전 로케일 + KO 레거시까지 전수**를 뜬다.
- **요청서의 대상 목록은 «요청서가 쓰인 시점»의 것이다.** 그 뒤 우리가 만든 자리는 우리가 찾는다.
  요청서의 분모·전제도 실측과 갈렸다 — **수치는 직접 센다.**
- **상대가 준 대체안도 검산하라**(08-16에 검수장 대체안이 틀렸다).
- **「없다」는 «내 출처에 없다»일 수 있다**(Rule 85는 WSOP엔 있고 TDA·RRoP엔 없다 — 둘 다 참).
- **검수장이 「덤」·「경미」로 적은 것을 먼저 파 봐라** — 덤이 지시보다 컸던 실례가 있다.
- **역방향 링크는 솔버 쪽 `ARTICLE_URLS`가 갖는다** — 포스팅 slug를 바꾸면 반드시 통지.

## 4. 라이브 확인 — «완료»라고 적을 때만, 10초짜리로

**배포는 «커밋»이 아니라 «그 시점의 상태 전체»를 민다** — 안 나간 커밋은 다음 배포에 자동으로 같이
나간다. 우리 레포는 `git push` = Vercel 자동 배포라 이 문제가 없다(수동 배포는 솔버 레포 사정).
08-22 사고의 진짜 원인은 «배포가 안 나간 것»이 아니라 **«문서가 나갔다고 적은 것»**이다.

| 상황 | 할 것 |
|---|---|
| 커밋만 함 | 아무것도 안 한다. 「커밋 완료 · 배포 대기」로 적으면 끝 |
| 문서·회신에 **「라이브에 반영됐다」**고 적을 때 | 🔴 그때만 확인 |
| **상대가** 「배포 완료」라고 통보해 왔을 때 | 🔴 확인 — 남의 말을 근거로 우리가 움직이기 때문 |

```bash
curl -s https://solver.holdemmaster.com/ | grep -oE '[a-f0-9]{20}\.js'   # 해시가 바뀌었으면 나간 것
```
전수 검사는 «새 언어 출시»처럼 판이 바뀔 때만.
