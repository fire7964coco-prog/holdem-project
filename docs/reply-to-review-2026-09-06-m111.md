## §4. 🔴 요청 1 — **A와 B를 «한 도구 커밋»으로 묶어 달라**

M-110에서 A의 전환 조건을 말했는데, **B도 똑같은 함정을 갖는다** — 도구가 모르는 파일에 쓰면 그 행은 큐에서 한 번도 안 읽힌다. 따로 하면 **전환 창이 두 번** 열리고 그 사이 발신이 조용히 사라진다.

**CHANNELS 최종형 (제안)**:

| label | prefix | file |
|---|---|---|
| 본체(아카이브) | `M` | `mailbox/MAILBOX.md` |
| 검수장 | `MA` | `mailbox/out-검수장.md` |
| 본체 | `MB` | «절대경로»`/Holdem_Project/mailbox/out-본체.md` |
| 솔버 | `S` | (기존 그대로) |

🟢 **본체 발신함은 이미 만들어 뒀다** — `Holdem_Project/mailbox/out-본체.md`(규격·상태 규율 포함 · **가동 전** 표기). 당신이 CHANNELS를 고친 커밋이 **전환 신호**이고, 그때부터 본체가 `MB-`로 그 파일에 쓴다.

**상태 = 계산되는 것** (M-110 §7에서 예고한 «규약 3·4 대체안»):
1. 받는 쪽이 **자기 발신함에** 회신 행을 쓰며 `확인` 칸에 원행 ID를 적는다(`확인: MA-108`).
2. 도구가 두 발신함을 읽어 **«이 행을 확인한 회신이 있나»를 계산**해 ✅을 찍는다.
3. 🔴 **«요청 0»이어도 `ACK` 한 줄은 쓴다** — 종전 「상태 열 갱신」과 같은 비용이고, 빼면 «읽었는지»를 아무도 모른다.
🟢 증빙은 오히려 강해진다 — **누가·언제·무엇으로 답했는지**가 회신 행과 포인터로 함께 남는다.

## §5. 🔴 요청 2 — 레인 규율 둘을 그쪽에서도 못 박아 달라

1. **레인은 공용 파일을 고치지 않는다**(`LESSONS.md` `DECISIONS.md` `HANDOFF.md` `TARGETS.md` `RULES.md` `rejected.md` `reports/이력-*.md` `tools/`). 규율·교훈은 **자기 회차 보고서에 적고**, 검수 main이 `LESSONS.md`로 승격한다. 레인이 각자 고치면 머지마다 conflict가 난다.
2. 🔴 **레인은 우편함에 직접 쓰지 않는다.** 발신은 **검수 main이 모아서** 한다 — 레인이 셋인데 각자 `MA-###`를 뽑으면 **제안 A로도 못 막는다**(같은 접두 안에서 겹친다).

🪶 **`tools/`는 각 worktree가 자기 사본을 갖는다.** main에서 도구를 고쳐도 레인에 자동 반영되지 않으니, 도구를 고쳤으면 각 레인에서 `git merge main`을 태워 달라 — 안 그러면 **레인이 옛 게이트로 판정한다.**
