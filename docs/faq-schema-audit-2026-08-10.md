# 다국어 FAQPage 스키마 감사 (2026-08-10)

> **왜 이 문서가 있나**: de 문체 게이트(D6)가 de 2편의 FAQ 스키마 0을 잡았는데, 원인을 파 보니
> **de만의 문제가 아니었다.** 같은 결함이 **EN 마스터를 포함해 15개 로케일 41편**에 있다.
> 지금까지 어떤 기계 검사도 이걸 보지 않았다 — 근거는 §3.

## 1. 판정 기준 (추측 아님 — 렌더러 코드가 진실)

`lib/intl-blog-page.tsx` L123이 FAQ를 뽑는 **유일한 정규식**이다:

```
/\*\*Q\.\s*([^*\n]+)\*\*\n\n?A\.\s*([^\n]+)/g
```

따라서 **셋 다** 지켜야 리치결과가 붙는다:

1. 질문이 `**Q. …**` 꼴 (질문 안에 `*` 금지)
2. 그다음 **빈 줄**
3. 답이 **`A. `로 시작하고 한 줄**

그리고 `faqItems.length >= 2`일 때만 FAQPage가 만들어진다.
→ **`###` 헤딩 FAQ도, `A.` 접두가 빠진 FAQ도 스키마가 0이다.** 사람 눈엔 멀쩡해 보인다.

## 3. 왜 지금까지 안 잡혔나 — 검사 자체가 없었다

- `audit:hard --schema`는 **`.next/server/app/blog/` 만** 본다 = **한국어 전용**.
  다국어 산출물은 `.next/server/app/<locale>/blog/`에 있는데 이 경로를 보는 코드가 없다.
- `check-de-style.mjs`의 D6은 **de만** 본다(2026-08-10 Session 0에 신설).
- 나머지 23개 로케일은 **원리상 미검사**였다.

→ [[review-mechanize-not-repeat]]의 「‘없다’ 보고 전 탐지 방법부터 의심하라」가 또 맞았다.
   hreflang(08-10 (5))과 **같은 병**이다: 검사가 있다고 «믿고» 있었을 뿐 없었다.

## 5. de는 어떻게 고쳤나 (참고 구현)

- `texas-holdem-rules-for-beginners` — `### 질문` 12개 → `**Q. …**` + 빈 줄 + `A. …`.
  이때 **H2와 축어가 같은 FAQ 3개는 지웠고**(정본 §7-6 중복 금지), 「Kurzversion」은 1번 항목과
  거의 같은 답이라 통합했다. 대신 독일어 실검색 롱테일 3문항(카드 수량)을 신설 → 최종 **11문항**.
- `holdem-game-order` — `**Q.`는 이미 있었고 **`A.` 접두만 빠져** 있었다. 7곳에 접두 추가 + Burn Card 1문항 신설 → **8문항**.
- 검증은 **빌드 산출물**로 했다: `.next/server/app/de/blog/*.html`의 `acceptedAnswer` 개수.
  소스 raw 카운트는 CRLF→LF 정규화 탓에 틀린다([[faq-schema-build-output-is-truth]]).
