### 🔴🔴 묶음 1~5가 값비싸게 증명한 것 — 6·7도 그대로 겪는다

1. 🔴🔴 **원장·인계서의 수치를 옮겨 적지 마라. 네 번 재계산해 세 번 어긋났다.**
   22 vs AKo 53.0 → **52.65%** · 22 vs AKs 49.9 → **50.11%**(부호 반전) · 모노톤 셋 29.0 → **34.44%**
   (원장이 아웃 카운팅의 **하한**을 적었다) · 버블 JJ $EV는 **재현 불가**라 수치를 빼고 구조만 고쳤다.
   ★발원지는 **FACTS §3 표 자체**였고 12항목 중 10항목이 «단일 조합»값이었다. 검수장이 전면 정정했다.
   **신설 규칙: 핸드타입 주장은 «가중평균»이 기본값. 단일 조합값 인용 금지**(글이 무늬를 명시한 실례일 때만 예외).
2. ★**검산 도구는 이미 있다. 다시 만들지 마라.** → `홀덤검수/tools/equity.mjs`
   `node tools/equity.mjs selftest` · `import { equity } from …` → `equity(["As","Ah"],["Ks","Kh"])`.
   7장 평가기 + C(48,5) 완전열거. ICM·버블팩터 식은 `WORKLOG.md` 2026-08-11 (2)에 있다.
3. 🔴 **되읽기 패스가 «내가 만든» 결함을 매 묶음 잡았다**(묶음1 4 · 묶음4 2 · 묶음5 4). **빼지 마라.**
   형태가 매번 바뀐다 — 묶음1~3 **새 낱말** / 묶음4 **남은 옛 문장**(삽입 뒤에 옛 수치가 살아 자기모순) /
   묶음5 **신설 행 내부 불일치**(de 표에서 형용사 ↔ 영어 명사형으로 품사가 갈림).
   → **삽입형 편집은 앞뒤를, 표를 쪼갰으면 쪼갠 두 행을 나란히 놓고 다시 읽어라.**
4. ⚙ **새 문장을 쓰기 전에 후보 낱말을 그 로케일 코퍼스에 grep해 히트 수를 세라. 사전은 기준이 아니다.**
   묶음5에서 5건을 쓰기 전에 걸렀다(de `überfolden` 0 · `Dauerdruck` 0 · pt `caçar` 0 ·
   id `beri kredit` 0 · es `sobrefoldear` 0). 그래도 pt `cace`가 새어 되읽기에서 잡혔다.
   과거 실례: de `Jamming-Range` · id 명사 `jam`=「시계」 · pt `range de jam`.
5. 🔴 **앵커 수는 인계 메모와 «양쪽으로» 어긋난다 — 언제나 직접 grep해 세라.**
   묶음1~4는 실측 **124곳**(메모 암시 64곳의 약 2배)으로 **과소**였고,
   묶음5 `split-pot`은 「표 행 + FAQ에도 반복」이라 적혔지만 **로케일당 팁 1곳뿐**으로 **과대**였다.
   한 주장이 본문·표 행·체크리스트·FAQ·링크카드 캡션에 흩어진다.
6. 🔴 **「이미 옳은 로케일」이 섞여 있다 — 기계 치환을 했으면 옳은 글을 되돌린다.**
   1단계 2곳(`rake`의 zh · `positions`의 de) · 묶음1(de·id·pt는 해당 FAQ 자체가 없음) ·
   묶음5(**de split-pot이 이미 정답이었고 유도값까지 일치**). 로케일별로 개별 판정하라.
7. ★**표 한 칸이 결함이면 칸이 아니라 «행 구조»를 의심하라.** `fish`는 성향이 정반대인 LAG/TAG를
   한 행에 묶은 게 결함이라 **처방 칸만 고치면 둘 중 하나는 반드시 틀린다.** 행을 쪼개는 게 유일한 답이었다.
8. **de·id·pt는 FAQ 문항이 7개뿐**이라 「FAQ에도 있다」가 해당 없는 경우가 잦다. **없는 문항을 만들지 마라.**
   (로케일별 FAQ 문항 수: `es 10 · zh 10 · en 9 · ja 9 · zh-hant 9 · de 7 · id 7 · pt 7`)
9. ⚙ **날짜는 `.mjs` 말고 Edit 도구로 바꿔라.** 외부 스크립트가 파일을 쓰면 하네스가
   **수정된 파일 전문을 컨텍스트에 덤프**한다(묶음 2·3·4에서 매번 터졌다). Edit는 안 그런다.

### 🔴 이 트랙이 증명한 것 — 3·4단계에도 그대로 적용

1. 🔴🔴 **한 사실이 8개 로케일에 복제돼 있으면, 한 로케일만 고치는 건 «고친 것»이 아니라 «어긋나게 만든 것»이다.**
   검수장은 **ja 원장만** 갖고 있어 ja만 잡았다. WPT Seminole 실례 2건은 EN 마스터 포함 **7개 로케일에 그대로** 살아 있었다.
   → **정정 절차에 「미러 전수 grep」을 붙여라.**
2. 🔴 **메모의 슬러그를 그대로 쓰지 마라 — KO 것이 섞여 있다.** A층·C층의 `when-to-fold-preflop-holdem`은
   **KO 슬러그**고 미러는 **`holdem-when-to-fold`**다. 미러는 KO 번역본이 아니라 **EN 파생본**이라 슬러그가 갈린다.
   ⚠ 이름이 같지만 서로 다른 원장인 10편이 있다(`blind-meaning`·`flush-vs-straight`·`game-order`·
   `hand-rankings`·`implied-odds`·`probability`·`split-pot-rules`·`strategy`·`tiebreak-rules`·`texas-…-beginners`) —
   **지시서에 나오면 항상 미러 쪽이다.**
3. **grep 히트를 그대로 믿지 마라.** `181` 히트 중 `wsop-2026-guide`는 준우승 상금 **$256,181**이었다.
4. **「직접 확인 필요」로 미확정 처리된 자리도 대개 결함이다.** `3bet` zh-hant가 그랬다(문구만 「後面沒人下注」로 달랐다).
   미확정을 «해당 없음»으로 읽지 마라.
5. 🔴 **오류가 「계산」이 아니라 「메커니즘 서술」에 몰린다** — WRONG 9건 중 **6건이 결론은 맞는데 이유가 틀린** 문장이었다
   (버튼이 액션을 닫는다 / 두 로열은 다른 무늬로만 / 캡이 «안 오른다»).
   **숫자를 보는 게이트가 원리상 못 잡는 층**이고, `audit:hard --locale=ja`는 이 9건 전부에 초록이었다.
6. **같은 오류가 본문과 FAQ 두 곳에 박힌 경우가 있다**(`positions` 187행 + 218행). **정정 전에 글 전체에서 grep.**
7. ★★**금지 규칙을 만나면 그 «이유»를 먼저 확인하라.** 「ja를 건드리면 원장 해시가 깨진다」는
   **본문에만 해당**한다 — 해시는 `tools/post-source.mjs`의 **desc+tldr+content**만 본다.
   그래서 ja `masterUpdated`만 올려 **드리프트 오탐을 막으면서** 재검수는 유발하지 않았다.
8. ★**글의 «자기모순»이 결함의 주된 형태다.** `icm`은 「리스크 프리미엄은 «콜»에 붙는다」를 이미 옳게
   적어 뒀는데 도입 경험담이 정반대로 가르쳤다. 검수장도 이 축을 받아들여 **C층 착수 전 전수 훑기**로 넘겼다.

### 🔴 de Session 1·2가 값비싸게 배운 것 — 3~6이 그대로 겪는다

1. 🔴 **「신설하라」고 적힌 항목이 이미 있었다**(대결표 7행). **인계서를 작업 지시서로 읽지 마라** —
   착수 전 대상 파일을 여는 것만으로 세션의 정의가 바뀐다.
2. **「게이트 🔴 N건」은 «게이트가 넓은 만큼만» N건이다.** Session 0의 6건은 틀린 값이 아니라 **좁은 값**이었다 —
   규칙을 넓히자 같은 42편에서 성 오류 **24곳** · 인용부호 **59곳**이 더 나왔다(셀프테스트 61→87).
   **새 결함 «유형»을 만나면 규칙을 넓히고 셀프테스트를 올려라.** 되읽기에서 «내가 만든» 오류를
   게이트가 못 잡으면 그게 넓히라는 신호다(`eine ganze Orbit` → `Orbit` 목록 + 형용사 슬롯 신설).
3. 🔴🔴 **게이트는 «성»을 보지 «격»을 안 본다.** 여성 `eine Raise`는 1·4격이 동형이라 격 오류가 가려져 있었고,
   게이트 지시대로 `ein Raise`로 고치는 순간 1격이 노출돼 동격의 격이 깨졌다.
   **일괄 치환 뒤에는 그 문장을 사람이 다시 읽어라.** 생략 명사도 같다
   (`dein Re-Raise ist die dritte **[Bet]**` — 주어를 보고 `der dritte`로 고치면 뜻이 바뀐다).
4. **매 실행 «미판정» 줄을 읽어라** — `prüfen` 17곳 · 천단위 쉼표 2곳 ·
   **`deine/keine + 남성 명사`**(복수와 동형이라 기계가 못 본다) · **관사 없는 형용사**(`als kleine Re-Raise`).
5. 🔴 **독일어는 «독일어 낱말로 쓴 영어 문장»에서 샌다.** 오독 3건 —
   `jede Straße`(street를 족보 Straße로! 하필 Straße를 가르치는 클러스터의 도입부) ·
   `unentschiedener Spieler`(=「우유부단한」) · `mieten`(=임차하다). 어휘 교정이 아니라 **문장 단위 재작성**이 필요하다.
   기계 게이트가 원리상 못 보는 자리(`mehrstöckige Aggression` = 「여러 «층»으로 된」 = 건물)에 사람 시간을 써라.
6. **드리프트의 정체를 찾는 3단** — ①**섹션별 줄 수** EN↔DE 대조 ②**1인칭 문장 수** 대조
   (EN 07-19가 넣은 **경험담이 안 온 게** 드리프트의 실체였다) ③**FAQ 질문 목록** 대조.
   🔴 **섹션 수가 맞아도 동기화된 게 아니다** — 드리프트 4편 모두 섹션 수는 정확히 일치했고
   **FAQ 질문 목록 대조만이** 18문항 누락을 잡았다. **3단 중 FAQ 목록이 주력이다.**
7. **개수를 맞추려고 준중복 FAQ를 넣지 마라.** tiebreak는 14:15로 남겼다 — EN 쪽이 자기 안에서 중복이다.

### 🔴 「판 전체 재동기화」를 착수한다면 — B1~B3에서 실제로 대가를 치른 7가지

1. **판정표를 믿지 마라 — 세 배치 연속으로 과소했다.** B1 E2 6→**10** · B2 C11 6→**23** · B3 「22개」→**23개**.
2. 🔴 **「틀린 패턴」을 정규식으로 찾지 마라.** 찾을 것은 «결함»이 아니라 **«그 주장을 담은 줄»**이다.
   결함을 검색하면 표기 편차에 전부 흘린다(`ja 80〜86%` 물결표 · `he בשולחן`). → 항목마다 해당 줄을
   **전 로케일에서 통째로 출력해 눈으로 판정**한다. `.mjs` 20줄이면 된다.
3. 🔴 **본문에 결함이 없으면 FAQ·tldr·표를 봐라.** B2 C5는 본문 24개 전부 정상인데 **FAQ만 22개가 틀려**
   같은 글 안에서 자기모순이었다. 고칠 땐 **그 로케일의 자기 본문 표현을 그대로 옮긴다**(새 번역 만들지 마라).
4. 🔴 **EN이 항상 정답은 아니다.** B2 C7은 **EN 마스터가 틀렸고** `zh`·`zh-hant`가 옳았다.
5. 🔴 **미러는 KO 번역본이 아니라 «EN 마스터 파생본»이다.** 슬러그도 다르다 —
   KO `holdem-pot-odds-calculation` ↔ 미러 `holdem-pot-odds` · KO `holdem-rules` ↔ `texas-holdem-rules-for-beginners`.
   **대조 전에 매핑부터 확인.**
6. 🔴 **치환은 `.mjs`로**(§16). 순서는 **드라이런 → 건수 검증(기대와 어긋나면 중단) → `--apply`**.
7. **masterUpdated는 «남은 항목이 없을 때만» 올린다.** ★역도 참이다 —
   **올라간 masterUpdated도 증거가 아니다**(`all-in-rules`가 07-25인 채 비어 있었다).
