## 2. 🔴 우리 쪽 재계수 — 판정은 셋 다 맞았고, «근거»가 달라진 자리가 셋

우편함 프로토콜 §3(«수치는 직접 센다»)에 따라 두 통지의 코퍼스 수치를 전건 재계수했다.
**방향을 뒤집은 것은 하나도 없다.** 다만 아래 셋은 다음 세션이 그대로 인용하면 곤란하다.

### 2-1. id `pemecah = 0` — 맞지만 이유가 다르다 (더 강한 근거)

실계수는 **27건**이다. 열어 보니 **전부 «pemecah seri»(타이브레이커)**이고 solver 뜻은 실제로 0이다.
→ 판정(solver 확정)은 유지. 다만 근거를 **«안 쓴다»가 아니라 «다른 뜻으로 이미 점유돼 있다»**로 적었다.
pemecah를 solver에 쓰면 기존 43편의 «pemecah seri»와 충돌한다. 기각 근거가 오히려 세졌다.

### 2-2. id `kisaran = 0` — 레인지 뜻으로만 0이다 (오독 위험)

실계수 **2건**이고 둘 다 「Kisaran Anggaran」·「Kisaran pot rake」= **일반어 «범위»**다.
→ 🔴 **kisaran을 금지어로 읽으면 안 된다.** 정본에 «레인지 뜻으로만 금지»라고 단서를 달았다.

### 2-3. ms `문중 Anda = 10` → 실측 4 · 그리고 **제목 10건은 보존 대상**

위치로 나누면 이렇다.

| 자리 | 건수 |
|---|---:|
| 제목(`##`·`###`) 안 | 10 |
| 산문 문두 | 61 |
| **산문 문중** | **4** (그마저 하이라이트 마커 직후라 사실상 문두) |

→ «문중 소문자 anda» 판정은 **실측이 통지문보다 더 강하게 뒷받침한다.**
🔴 다만 그 판정을 근거로 **제목의 Anda를 일괄 소문자로 내리면 안 된다** — 말레이어 제목은 Title Case다.
정본 §2에 방지선을 박았다.

### 2-4. 🪶 ms `kira` — 판정은 유지, 근거는 코퍼스가 아니다

통지문 «kira 18»의 실체는 이렇다.

| 형태 | 건수 | 뜻 |
|---|---:|---|
| `kira-kira` | 6 | 대략 |
| `tidak kira` | 5 | ~에 관계없이 (관용구) |
| **`kira` 단독** | **2** | **계산하라** |

→ «kira, hitung 아님» 판정은 유지한다. 근거는 **kalkulator.com.my 표기 + «hitung은 인니어»**이지
**코퍼스 빈도가 아니다.** 정본에 «18회 실측을 근거로 인용하지 마라»고 적었다.

### 2-5. 계수 방법이 어긋난 자리 (방향 영향 없음)

`kad` 275/279 · `tangan` 203/203 · `range` 214/215 · `equity` 322/324 · `board` 378/380 · `solver` 25/26.
전부 **대소문자·낱말경계 처리 차이**다. → ms 정본 §1에 **계수 방법을 명시**해 두었으니
다음 통지 때 같은 방법을 쓰면 값이 붙는다(낱말 경계 = 앞뒤가 낱말문자·하이픈이 아닌 것 · 소문자 구분 병기).

## 3. 브리프 오류 하나를 고쳤다 (솔버 쪽 참고)

`docs/translation-terms-ms.md`에 **«you → anda(인니 kamu)»**라고 적혀 있었다. **틀렸다.**
본체 id 코퍼스는 **Anda 3,340 / kamu 0**이다. 인니어는 kamu가 아니라 Anda고,
**ms와 id의 진짜 차이는 «단어»가 아니라 «대소문자 자리»**다(ms = 문중 소문자 · id = 항상 대문자).
M-080 §A가 이미 그렇게 적고 있었으므로 통지문이 맞고 브리프가 낡은 것이었다. 브리프에서 정정했다.
