## 1. 원칙 (사장님 10-03 · 1차 + 2차 결정)

1. **사람 먼저, 기계는 따라온다.** 쓰기 쉽게(필수 = 글 한 칸). AI·검색 가독성은 후기를 **서버 렌더 HTML**로 내보내 얻는다(§6). 브라우저에서만 불러오면 봇에겐 빈 페이지.
2. **요청 없이 «자리»만** — 앱 메뉴 · 결과 화면 아래 한 줄 고정 + **3번째 솔브 뒤** 결과 아래 한 줄 1회. 팝업·반복·보상 없음.
3. **받는 곳 = 앱 안(쓴 직후) · 보이는 곳 = 그 언어 랜딩.** 같은 Supabase · 랜딩에도 입력 칸(후기와 질문을 한 블록 · 종류로 구분) · 질문 → 운영자 답글 → FAQ 승격.
4. **쓰면 바로 보인다**(2차 A) — 후기도 댓글처럼. 승인 대기 없음. 숨김은 사후에, **링크·욕설·광고 세 사유만**. 부정 후기는 지우지 않는다(블록 상단에 명시).
5. **누구나 쓴다**(2차 E) — 사용 횟수 문턱 없음. «잘 쓰겠습니다» 한 줄 감사도 후기다. 대신 **«사람이 각자 쓴 것»이 보이게** — 구글·카카오 이름과 프로필 사진이 붙는다(§4-1).
6. **이벤트는 이벤트 칸에서**(2차 F·K·L) — 후기창엔 보상·응모·«이벤트 참여» 꼬리표가 없다. 후기를 더 끌어내고 싶으면 이벤트 쪽을 바꾼다(그건 이 문서 밖).
7. **우리가 못 하는 말은 유저가 한다** — «위자드만큼 좋아요»는 유저가 우리에게 보내는 찬사다(2차 J). 지우지도 거르지도 않는다. 단 **우리가 그 말을 가져다 광고 문구로 쓰지는 않는다**(§5-3).
8. **전 언어 동시 개통**(2차 D) — 앱 12개 언어 = 랜딩 12개.

## 2. 화면 — 편하게 쓰게 (UI·UX)

### 2-1. 쓰기 흐름 (앱·랜딩 공통 — 폰 한 화면)

```
┌ 솔버 써 보니 어땠나요? ─────────────────┐
│  ☆ ☆ ☆ ☆ ☆        ← 탭 한 번 (선택)     │
│ ┌────────────────────────────────────┐ │
│ │ 한마디 남겨 주세요                   │ │  ← 열리자마자 커서
│ │                                      │ │
│ └────────────────────────────────────┘ │
│  + 아쉬운 점도 적기 (접힘)               │
│                                          │
│  [G] 하봄 으로 남깁니다                  │  ← 로그인돼 있으면 이름·사진 미리보기
│              [ 남기기 ]                  │
└──────────────────────────────────────────┘
```

| 원칙 | 구체 |
|---|---|
| 칸은 하나 | 필수 = 본문 한 칸. 별점·아쉬운 점은 선택이고 아쉬운 점은 접어 둔다 |
| 별점은 탭 한 번 | 큰 별 5개(손가락 크기 44px 이상) · 다시 누르면 해제 · 별점만 누르고 본문을 비우면 «한마디만 남겨 주세요» 안내(글 없는 별점은 받지 않는다 — 봇·스팸 구별) |
| 짧아도 된다 | 본문 **2~600자**(댓글 규칙 `COMMENT_BODY_MIN = 2`와 같게) — «감사합니다», «잘 쓸게요» 그대로 통과 |
| 로그인은 마지막에 | 글을 먼저 쓰게 하고, [남기기]를 누를 때 로그인 안 돼 있으면 구글·카카오 버튼(카카오는 ko만) → 돌아오면 **쓴 글 그대로 자동 등록**(초안은 기기에 임시 보관) |
| 바로 보인다 | 등록 즉시 목록 맨 위에 내 후기 + «수정 · 삭제» |
| 링크를 쓰면 | 등록 막지 말고 그 자리에서 «링크는 넣을 수 없어요» 표시(입력 중 실시간) |
| placeholder | 중립 — «한마디 남겨 주세요» / «좋았던 점도 아쉬운 점도 그대로». 솔버 수치·비교·기능 약속을 넣지 않는다(유도 흔적 · 사실 시트 §4·§5). 12언어 문구는 §5로 검수 |

- 기기 = 자동(폰/태블릿/PC 세 값 · 모델명 저장 안 함).
- 1인 1언어 1후기(다시 쓰면 기존 후기 수정 화면으로) · 질문은 개수 제한 없음(속도 제한만).
- 🔴 로그인은 도메인마다 따로다 — 앱(솔버 도메인)과 랜딩(본체)에서 각각 한 번. 같은 계정이면 같은 이름으로 나온다.

### 2-2. 앱 안 자리 (솔버 세션이 구현 — §8 요청 ①)

| 자리 | 언제 | 모양 |
|---|---|---|
| 앱 메뉴 | 항상 | «후기 남기기» |
| 결과 화면 아래 | 항상 | 작은 글씨 한 줄 «써 보니 어땠나요?» |
| 결과 화면 아래 (1회) | **3번째 솔브 완료** 직후 그 결과 화면에서만 | 고정 줄과 별도의 한 줄 · 닫기 버튼 없음 · 다음 결과부터 안 나온다 |

누르면 §2-1 폼이 **앱 안에서** 열린다(본체로 이동시키지 않는다).

### 2-3. 랜딩 «써 본 사람들» 블록

위치 = FAQ **바로 위**(랜딩 2번째 섹션은 영상 자리라 비운다).

```
┌ 써 본 사람들 ─────────────────────────────────┐
│ 후기 N · ★ 4.6 (별점 R개)                       │ ← 요약 한 줄 (§3-3)
│ ⓘ 부정적인 후기도 지우지 않습니다.               │
│   숨기는 것은 링크·욕설·광고뿐입니다.             │
│ [ 쓰기 칸 — §2-1 ]                              │ ← 목록보다 위: 읽기 전에 쓸 수 있게
│ ─────────────────────────────────────────── │
│ 대표 후기 (도움됐어요 순 2~3개)                  │
│ (사진) 하봄 [G] · 2026-10-12 · 폰 · ★★★★★      │
│ "본문"                                          │
│ ↳ 운영자: …                                     │
│ 👍 도움됐어요 5                                  │
│ ▸ 전체 후기 보기 (최신순)                         │
│ ─────────────────────────────────────────── │
│ 질문 (답변 / 답변 대기)                           │
└───────────────────────────────────────────────┘
```
※ 배치만 보인다 — 예시 문장은 화면 문구가 아니다.

- **전체 목록도 서버 HTML에 넣고 `<details>`로 접는다**(원칙 1).
- 빈 상태:

| 상태 | 화면 |
|---|---|
| 후기 0 | 쓰기 칸 + «첫 후기를 남겨 주세요» · 요약·대표 없음 |
| 후기 1~2 | 쓰기 칸 + 목록(대표 구분 없이) · 요약 줄 숨김 |
| 후기 3 이상 | 요약 + 대표 2~3 + 전체(details) |
| 질문 | 1개 이상이면 보인다(문턱 없음) |
| 내 후기가 숨겨졌을 때 | 본인에게만 «숨김 · 사유 ○○ · 다시 검토 요청» |

## 3. 신뢰 — «봇이 아니라 각자 다른 사람»이 보이게 (2차 E)

### 3-1. 한 후기에 붙는 것

| 신호 | 왜 |
|---|---|
| **이름 + 프로필 사진** — 구글·카카오 가입 때 자동으로 들어간 값(`profiles.nickname` = 계정의 `name` · `avatar_url` · `supabase/schema.sql` 가입 트리거) | 사람마다 다른 이름·얼굴. 봇 글은 이게 비거나 똑같다 |
| **로그인 수단 표시** [G] / [카카오] | «실제 구글·카카오 계정으로 쓴 글»이라는 신호 |
| 날짜(일 단위) · 기기 | 날짜가 흩어져 있으면 몰아 쓴 글이 아니다 · 기기는 읽는 사람이 자기 상황과 맞춰 본다 |
| 1계정 1후기 | 같은 사람이 여러 번 못 쓴다 |
| (있으면) «솔버 사용 기록 있음» | 트레이너 기록이 있는 계정 — **문턱이 아니라 덧붙는 표시**. 개인 횟수는 공개 안 함 |

- 🔴 **이름 공개 안내**: 폼에 «[G] 하봄 으로 남깁니다 [이름 바꾸기]» — 구글 이름이 실명일 수 있으니 쓰기 전에 보이게 하고, 바꾸면 profiles 닉네임이 바뀐다. 🔴 구글 이름이 비어 이메일 앞부분이 닉네임으로 들어간 계정(가입 트리거의 대체값)은 **이메일 일부가 공개되는 셈**이라, 그 경우엔 폼에서 이름을 먼저 정하게 한다.
- 개인정보처리방침에 «후기에 공개되는 항목(이름·사진·날짜·기기·별점)» 추가(코드 회차).

### 3-2. 숨김·운영
- 숨김 사유 = **링크 · 욕설 · 광고** 세 개뿐(DB 제약으로 강제 — 관리자 화면에 다른 선택지도, 삭제 버튼도 없다). 정의(고지 «기준 펼치기»): 링크 = 외부 주소 · 욕설 = 특정인 비하·비속어(제품에 대한 강한 비판은 해당 없음) · 광고 = 다른 서비스·상품 홍보.
- 숨기면 작성자에게 사유를 보여 주고 «다시 검토 요청» 1회.
- 운영자 답글 = 관리자 화면 한 칸. 부정 후기엔 해명이 아니라 사실(«검토 중» · 안 하기로 한 것은 이유 — 예: 멀티웨이는 안 한다). **출시일·기능 약속 금지**(사실 시트 §4).
- 운영자·관계자는 «도움됐어요»를 누르지 않는다.

### 3-3. 요약 한 줄 · 대표
- 형식 = `후기 N · ★ 평균 (별점 R개)` — 후기 3개 이상일 때만 · 평균은 별점 R ≥ 5일 때만(가정).
- 대표 2~3개 = «도움됐어요» 많은 순 → 최신. **운영자가 고르지 않는다**(부정 후기도 후보).
- «도움됐어요» = 로그인 1인 1표(익명이면 저장소를 지워 표를 늘릴 수 있다 — 색인되는 대표 자리라 막는다). 숫자는 클라이언트에서 갱신.
- 대표 재정렬 = 기존 매일 재빌드 크론(`vercel.json` `/api/cron/rebuild`).

## 4. 질문 → FAQ

1. 질문도 **바로 «답변 대기»로 보인다.**
2. 운영자 답글이 달리면 «답변».
3. **같은 질문이 3건 이상 모이면** 그 언어 `faq.ts`로 승격(화면 FAQ + FAQPage 스키마 같은 배열). 답은 사실 시트 §5·플레이북 §4-8로 다시 쓴다.

## 5. 문구·법 관련 정리

### 5-1. 링크 차단 규칙 (09-28)
09-28 참여 장치(대회 후기·투표 댓글)에서 만든 스팸 방지 규칙 — 본문에 `http://`·`www.`·`.com/`·`.kr` 같은 주소가 있으면 저장을 거부한다(`lib/participation-config.ts` `LINK_PATTERN` + `supabase/participation.sql` DB 제약 이중). 후기창도 같은 규칙을 공용으로 쓴다. 그래서 «스팟 공유 링크»는 본문이 아니라 별도 칸으로 받는다(§7-2).

### 5-2. Review 스키마 = 넣지 않는다 (2차 C — 본체 판단)
Review·AggregateRating 스키마는 «검색 결과에 별점이 뜨게 해 달라»는 표시인데, **자기 사이트가 자기 제품 후기를 표시하는 경우 구글은 별점을 띄워 주지 않는다**(self-serving 정책). 얻는 것이 없고, 규칙 위반으로 읽히면 수동 조치 위험만 있다. → 09-28 결정 그대로 **넣지 않는다**. 후기 본문이 HTML로 있는 것만으로 검색·AI가 읽는다(§6).

### 5-3. «위자드만큼 좋아요» (2차 J)
- 유저 후기 안의 비교 = **유저의 찬사**. 목록·대표 어디서든 그대로 둔다.
- 🔴 다만 **우리가 그 문장을 뽑아 광고 문구로 쓰는 것**(영상 자막·FAQ 답·PWA 한 줄·랜딩 본문 인용)은 «우리가 비교 광고를 한 것»이 된다 — 사실 시트 §5 «유료 솔버와 비교 금지»가 적용된다. 요약 한 줄·PWA 한 줄은 **숫자만** 쓴다.

### 5-4. 이벤트와의 관계 (2차 F·K·L)
- 후기창엔 응모 체크·꼬리표·연령 확인이 없다.
- 🪶 나중에 이벤트 칸에서 «솔버 후기 쓰면 ○○»를 열게 되면, **그 이벤트로 쓴 후기에는 표시 의무**(공정위 추천·보증 심사지침 — 대가를 받은 후기)가 생긴다. 그때 이벤트 설계에서 꼬리표를 붙인다(09-28 대회 후기 `is_event_entry` 방식). 지금 데이터 모델엔 그 열만 비워 둔다.

## 6. 색인·AI 가독성

- 랜딩은 SSG다. 후기 블록 = **서버 컴포넌트, 쿠키 없는 admin 클라이언트로만 읽는다** — `lib/supabase/server.ts`(cookies)를 쓰면 랜딩이 동적 라우트가 돼 `.html`이 사라지고 `check-hreflang`·`check-directives`가 못 본다. → 게이트: 빌드 산출물에 12개 `solver.html` 존재.
- 갱신 = ① 후기 등록·수정·숨김 때 `revalidatePath`(로케일 → 경로 매핑 함수 하나 · KO = `/solver`) ② 매일 재빌드. `export const revalidate`는 넣지 않는다.
- 빌드 env에 서비스 키가 없으면 빈 블록이 하루 굳는다 → 빌드 경고 + 게이트 🔴.
- 정적 페이지 on-demand `revalidatePath` Vercel 실측 = 미확인 → 개통 직후 라이브 확인.
- 언어마다 후기가 다른 것 = 의도된 차이 → `docs/locale-intentional-diffs.md`에 한 줄.
