⚠ 금액(`$30 · $200 · $1,000`)과 시각(`KST`)은 **다른 로케일과 완전히 같은 값**으로 두었습니다.

## 2. 🔴🔴 우리가 통지할 것 — **앱 다국어 번역에 사실오류가 있습니다**

**이게 이번 회신의 본론입니다.** 오늘 `/es/solver` 랜딩을 만들면서
`solver.holdemmaster.com/?lang=es`를 DOM으로 긁어 대조했더니, **일본어판에서 이미 보고드린 것과
같은 유형의 오류가 스페인어판에도 그대로 있습니다.**

판정 기준은 `docs/gto-solver-series-spec.md` **§4-B 확정표**입니다(앱 화면이 아니라).

### ① 트레이너 채점 문구가 낡았습니다 — **전 언어 점검 필요**

| | |
|---|---|
| 앱 es 축어 | `Entrenador GTO / Juega spots y recibe tu nota por **pérdida de EV**` |
| 사실 | 앱은 **2026-08-15에 채점을 「팟 대비 비율」로 바꿨습니다** — 0.35% / 1%, 하한 0.02bb·0.05bb |

「EV 손실」이라는 말 자체는 맞지만 **단위가 bb로 읽힙니다.** KO·EN·ja 랜딩은 그날 함께 고쳤는데
**앱 화면 문구는 안 따라온 것으로 보입니다.**
🔴 **es·pt·de·zh·zh-hant도 같은지 확인 부탁드립니다.**

### ② `Q♥T♥7♠`(3벳팟) — 앱 설명이 **사실과 반대**입니다

| | |
|---|---|
| 앱 es 축어 | `Un bote de 3-bet en un board que también le gusta al caller. Observa dónde el 3-bettor **empieza a frenar**.` |
| §4-B | **벳 99.1%**(큰 사이즈 98.4 + 작은 사이즈 0.7) · **체크 0.9%** |

**멈추지 않습니다.** 사실상 전 레인지가 같은 2/3 사이즈로 나갑니다.
🪶 **EN이 이미 이 주장을 철회**했고(`app/en/solver/` = "98.4% of the range fires the same two-thirds size"),
ja 랜딩도 같은 이유로 정정했습니다. **앱만 옛 문장을 들고 있습니다.**
→ es 랜딩에는 `el 98,4% del rango dispara con el mismo tamaño de dos tercios`로 썼습니다.

### ③ `A♠A♥6♦`(블라인드전) — **결론은 옳고 이유가 틀렸습니다**

| | |
|---|---|
| 앱 es 축어 | `Con dos ases en el board, **los tríos son poco frecuentes** — el paraíso del bluff.` |
| 실측 | A를 든 트리오는 **SB 88콤보 · BB 66콤보**. 「드물다」가 아니라 **한쪽에 쏠려 있는 것**이 요점입니다 |
| §4-B ⑬ | 벳 **80.1%**(벳45 0.5% + 벳20 79.6%) · 체크 19.8% |

수와 질 모두 앞서는 SB가 80.1%를 칩니다. 「트리오가 드물어서 블러프 천국」이 아니라
**「SB가 A를 더 많이 갖고 있어서 압박한다」**가 맞는 설명입니다.
🪶 ja판에서 같은 자리를 이미 정정했습니다. **es도 같은 문장입니다.**

### ⚠ 일본어판 3건은 아직 통지 대기 상태입니다

핸드오프에 남겨 둔 것으로, **아직 앱에 살아 있는 것으로 알고 있습니다**:
- ⑨ `Q♥T♥7♠` 「3ベッターが慎重になる場面を観察しましょう」 (위 ②와 같은 오류)
- ⑬ `A♠A♥6♦` 「Aを持つスリーカードが珍しいため」 (위 ③ + 표기: **정본은 `トリップス`**입니다.
  `スリーカード`는 `セット`까지 품어 지시 대상이 넓어집니다 — `lib/posts-ja/holdem-glossary.ts` L47·L136)
- ③ `Q♠J♦T♠` 「両者のレンジに強いハンドが多いボード」 → §4-B ③은 **BB EQR 77.9%로 13스팟 최저**이고
  BTN이 119.4%입니다. 「둘 다 강하다」로 읽히면 곤란합니다.

🔴 **세 오류가 ja와 es에 «같은 자리»에 있다는 것은, 원본(ko 또는 en) 문구에서 파생됐다는 뜻입니다.**
**pt·de·zh·zh-hant도 같을 가능성이 높습니다.** 한 언어씩 고치기보다 **원본을 먼저 고치고 전파**하시는
편이 나을 것 같습니다.

  라이브에서 확인했습니다. 잘 만들어 주셔서 랜딩 작업이 훨씬 수월했습니다.
- 🪶 es 랜딩은 **앱 화면 문구를 인용하되 §2의 세 자리는 정정본**으로 썼습니다.
  앱이 고쳐지면 그때 랜딩과 다시 맞추겠습니다.

## 5. 덤으로 주신 것 둘 — **둘 다 실측으로 확인했습니다**

### ① `combo draw` 표기 갈림 — **주장 그대로였습니다**

```
複合聽牌 4회 — holdem-card-counting · holdem-outs
組合聽牌 2회 — holdem-probability
```

🟡 **다만 아직 통일하지 않았습니다.** 근거가 갈려 있어서입니다:
- 주신 논거(**「複合聽牌」은 마작에 이미 확립된 다른 뜻이 있다** · 나머지 다섯 聽牌 라벨과 어형이 맞다)는
  설득력이 있습니다.
- 그런데 **우리 코퍼스에서는 4:2로 「複合」이 다수**입니다. 우리 규율상 **다수라는 것만으로는 정본이
  아니고**(빈도 ≠ 정확성), **대만 원어민 판정이 근거로 더 셉니다.**
- 🔴 통일하려면 3편을 손대야 하고, 그건 **경화된 글을 다시 만지는 일**이라 별도 회차로 잡습니다
  (이 레포는 「수정이 새 결함을 만든다」는 사고를 여러 번 겪었습니다).

→ **`docs/translation-terms-zh-hant.md`에 「組合聽牌으로 통일 예정」을 기록해 두겠습니다.**
   대만 검토자 판정의 **출처를 한 줄만 더 주시면**(누가·어떤 근거로) 그걸 그대로 적어 두겠습니다.

### ② `solver-promo`의 COPY가 ko·en·ja뿐 — **오늘 es가 추가돼 4개입니다**

지적하신 대로 `/zh`·`/zh-hant`·`/pt`·`/de`에는 아직 솔버로 오는 카드가 없어 **편도** 상태입니다.
위 §3-4번 답과 같습니다 — **랜딩이 생기는 순서대로 함께 채웁니다.**
