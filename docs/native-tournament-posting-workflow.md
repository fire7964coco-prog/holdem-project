# 대회 글 — 언어별 순수 집필 워크플로우

> **번역이 아니다.** 대회라는 소재만 공유하고, 나머지는 해당 언어로 새로 쓴다.
> 확정: 2026-07-30. 이전 방식(ko/EN 마스터 → 번역)은 이 문서로 대체된다.

---

## 0. 왜 번역을 버렸나 (다시 흔들리지 않기 위한 기록)

`apt-jeju-2026-fall-guide`(ko)의 **첫 H2**가 근거다.

```
## 한국 국적자도 참가할 수 있나요? — LES A는 외국인 전용
```

제주 LES A는 외국인 전용이라, **한국 독자에게 이 글의 첫 관문은 "입장 가능 여부"**다.
그런데 일본·대만·중국 독자는 한국에서 외국인이므로 **애초에 문제가 아니다.**
번역하면 **존재하지 않는 문제를 첫 줄에서 다루는 글**이 된다. 문체가 아니라 논지가 틀린다.

| ko 전제 | CJK 독자에게는 |
|---|---|
| 제주까지 김포 국내선 | 나리타·간사이·타이베이 **직항 국제선** |
| 여권 + 영주권 카드 둘 다 | **여권 하나면 끝** |
| 입장 조건이 최대 난관 | 입장은 문제없음 → **일정·비용**이 관심사 |
| 제주 무비자 → 언급 없음 | **핵심 셀링포인트** (ko판에 아예 없는 내용) |

번역은 왼쪽 열을 옮긴다. 독자에게 필요한 오른쪽 열은 원문에 없으니 나올 수가 없다.

**부수 효과가 더 크다.** 순수 집필로 가면 대회 슬레이트를 언어별로 고를 수 있다.
일본 독자에게 최적은 한국 대회가 아니라 **JOPT(자국)**, 대만은 **타이베이 자국 시리즈**다.
번역으로는 애초에 만들 수 없는 슬레이트다.

## 1. 진행 축 = **언어별** (대회별 아님)

대회별의 유일한 장점은 "스파인 한 번 읽고 N개 언어를 써서 수치가 안 어긋난다"인데,
그건 §5의 **숫자 불변 검사 스크립트**로 없앤다. 그 뒤엔 언어별이 전부 이긴다.

1. **비싼 건 사실이 아니라 목소리다.** local-voice + 현지 검색 결과 + 용어 표기 + 레지스터를
   머리에 올리는 게 비용의 대부분이다. 한 번 올려 N편을 쓰면 분산된다.
   편마다 언어를 바꾸면 매번 다시 올려야 한다 → 2026-07-29 CJK판이 번역 티가 난 원인.
2. **슬레이트가 언어마다 다르다.** ja=JOPT, zh-hant=대만 시리즈로 안 겹치는 글이 많다.
   대회별로 묶으면 대부분 "1개 언어 배치"가 되어 묶는 의미가 사라진다.
3. **적대적 검수가 자연히 배치된다.** 현지 전문가 페르소나 하나가 그 언어 전편을 한 번에 본다
   (기존 관행 `배치 종료 시마다 적대적 QA`와 일치).

## 2. Phase 0 — 대회 선정 (글쓰기 전에 반드시)

### 2-1. ★ 지난 대회 걸러내기

`lib/tournaments.ts`의 `startDate`/`endDate`로 오늘 기준 상태를 계산한다.
**끝난 대회에 "참가 방법" 글을 쓰면 발행 즉시 죽은 콘텐츠다.**

> 실제 사고: 2026-07-30에 `holdem-masters-7th-guide`의 3개 언어판을 만들려다,
> 대회가 **8/2 종료(D-3)** 인 것을 확인하고 탈락시켰다. 확인 안 했으면 9편 중 3편이 낭비됐다.

### 2-2. ★ 리드타임 게이트

| 리드타임 | 판단 |
|---|---|
| **D-28 이상** | ✅ "참가 방법" 글 가능 (위성·등록·항공·숙소를 독자가 실행할 시간이 있다) |
| D-8 ~ D-27 | ⚠️ 등록 마감·위성이 이미 끝났을 수 있음. 일정·관전 중심으로 축소 |
| D-7 이하 / 진행중 | ❌ 참가 가이드 금지. 결과 아카이브로만 |

### 2-3. 시장별 우선순위

**자국 대회 > 근거리 대회 > 원거리 메이저**

자국 대회는 비자·항공·언어 장벽이 0이라 전환이 가장 높고, 현지어 검색 경쟁도 약하다.

| 언어 | 자국 | 근거리 |
|---|---|---|
| `ja` | JP (JOPT) | KR · TW · PH · VN |
| `zh-hant` | TW | KR · PH · JP · VN |
| `zh` | (없음) | PH · KR · VN · TW · AU |
| `es` | (없음 — LATAM 기준) | MX · AR · BR · PA + 원거리 유럽 |
| `en` | US | 유럽 · BS · CA |

원거리 메이저(WSOP·EPT)는 **브랜드 검색량 자체가 커서** 자국 대회가 없는 언어(zh)에서는
여전히 1순위가 될 수 있다. 기계적으로 배제하지 말 것.

## 3. Phase 1 — 참고 파일 정독 (★ 4계열이다. 하나만 읽으면 사고 난다)

> **2026-07-30의 실제 사고**: `local-voice/ja-jp.md`만 만들고 작업했는데,
> **`translation-terms-ja.md`(201줄)에 「시차」·「円 환산」·「APT 인천 37.8% 훅」이
> 이미 7-28에 기록돼 있었다.** 그걸 "새로 발견"하며 중복 파일을 만들었고,
> 같은 파일의 ★3(선수명 로마자 어순)은 **규칙이 있는데도 글에 적용이 안 된 상태**였다.
> → 아래 4계열을 **번호 순서대로** 훑는다.

| # | 파일 | 무엇이 있나 | 커버 |
|---|---|---|---|
| **1** | **`docs/translation-terms-<lang>.md`** ★**정본** | 용어 · 문체 · H2 형태소 · 배치원칙 · 정책 · **교정 사례** | **24개 언어** |
| 2 | `docs/market-profile/<lang>.md` | 비자 · 세금 · 통화 · 사업자 · 합법성 | 6개(en·es·ja·ko·zh·zh-hant) |
| 3 | `docs/keyword-bank/<lang>-*.md` | 실측 키워드 · 질문 DB · 화이트스페이스 | 3개 언어(en 11 · es 5 · ja 1) |
| 4 | `docs/local-voice/<lang>.md` | **진입점(라우팅) + 독자 특성**. 얇게 유지 | ja 1 · es 2 |

**정본은 1번이다.** 용어·교정사례를 4번에 적지 않는다(중복이 되고 어느 게 맞는지 알 수 없어진다).
키워드 실측치는 3번에만 둔다.

### 없는 파일을 만들 때

`local-voice/`가 없는 언어는 **3~4번을 새로 만들되 1번을 먼저 정독**한다.
1번에 이미 있는 내용을 옮겨 적지 말고, **1번에 없는 것만** 새 파일에 넣는다.

**어느 파일에 무엇을 적나** (섞으면 정본이 사라진다)

| 내용 | 들어갈 파일 |
|---|---|
| 용어 표기 · 문체 · H2 형태소 · 배치 원칙 · 편집 정책 · **교정 사례** | **1번 정본** |
| 비자 · 세금 · 통화 제도 · 입국 절차 | 2번 market-profile |
| 실측 키워드 · 질문 DB · 화이트스페이스 | 3번 keyword-bank |
| 파일 라우팅 · 독자 인지 수준 · 필자 인칭 정책 | 4번 local-voice (**얇게**) |

`es`는 방언 계파·voseo·슬랭이 있어 4번이 두껍다(`es-latam.md` 193줄).
`ja`는 방언 분기가 없어 4번이 얇다(82줄) — **언어마다 4번의 두께는 다른 게 정상**이다.

> 파일은 **글을 쓰면서 자란다.** 1편에서 배운 걸 적고 2편이 그걸 쓴다.
> 다만 **append 대상은 위 표대로 고른다.** 교정 사례를 4번에 적으면 정본이 둘로 갈린다.

## 4. Phase 2 — 편당 집필 루프

### 4-1. 사실 스파인 읽기 (재조사 금지)

**`docs/tournament-spine.md` + `lib/tournaments.ts`가 유일 출처.**
날짜·바이인·GTD·회장·구조·엔트리 수는 **여기서만** 가져온다.

언어별로 사실을 다시 조사하지 않는다. §13 오류가 늘어나는 지점이 정확히 여기다.
스파인 값이 의심되면 **코드가 아니라 스파인에 적힌 원문 URL을 다시 연다.**

### 4-2. 현지 웹서치 3회 (§12-B 준수)

**서치 대상은 사실이 아니라 "현지 독자의 문제 설정과 표현"이다.**

- WebSearch = **URL 찾기 전용**. 검색 요약의 내용을 사실로 쓰지 않는다
- WebFetch = 단일 사실만, **축어 인용 요구** 필수
- **열거·개수는 Playwright**로 DOM을 긁어 직접 센다 (요약 금지)

3회의 각도를 다르게 잡는다:
1. 현지어로 그 대회명 검색 → 현지 매체·커뮤니티가 뭘 궁금해하나 (PAA·질문)
2. 현지어로 "그 나라 → 개최지" 이동/입국 검색 → 실제 경로·소요시간
3. 현지 포커 커뮤니티 글 → 표현·용어·관심사 (상금? 필드 수준? 숙소?)

### 4-3. 집필 (현지 전문가 페르소나)

- **ko 원문을 열어놓고 쓰지 않는다.** 열면 구조를 따라간다
- H2는 §4-2에서 실측한 **현지 검색 형태소**로. 질문형이 현지에서 안 쓰이면 명사형으로
- **경험담 필수** (E-E-A-T). 없는 사실을 만들지 말고, 일반화 가능한 관찰로 쓴다
- 상단 `tldr`은 2~3줄 자기완결 직답 단락
- 내부링크 최소 3개 + FAQ 앞 `:::readnext` 카드
- 이미지: 실사 기본, 글자 들어가는 인포그래픽은 AI 금지(HTML+Playwright), 워터마크 우하단

### 4-4. 🔴 절대 금지

- **합법/불법 프레이밍 금지.** 대회 참가·관전을 위법 소지로 묘사하지 않는다.
  입국 절차·비자면제·연령 제한 같은 **실무 정보는 사실로 기술**하되, 그것을 "불법" 논의로
  끌고 가지 않는다. 부정형 결론으로 글을 닫지 않는다
- 검산 없는 핸드 예시 (§13)
- 환율 고정 환산을 본문에 박기 (환율이 움직인 순간 거짓이 된다 → 기준점만)

## 5. Phase 3 — 배치 검수 (언어 하나 끝날 때마다)

### 5-1. 숫자 불변 검사 (기계)

각 언어판에서 숫자·날짜·통화를 추출해 **스파인과 대조**한다.
언어별 집필의 유일한 구조적 약점이 수치 드리프트이고, 이걸로 막는다.

> 근거: 예전에 "각 문장은 참인데 문서끼리 모순"으로 12건을 정리한 적이 있다.
> 정확성과 내부 일관성은 별개 축이다.

단위 표기는 언어별로 달라도 된다(15억 → `15億ウォン` / `15亿韩元`).
**값이 달라지면 안 된다.**

### 5-2. 적대적 네이티브 검수 (Agent)

그 언어 현지 홀덤 전문 기자 페르소나로 배치 전편을 한 번에 검수.
용어 표기 · 자연스러움 · 신규 H2의 사실성 · 현지 관습 위반 · 톤.

> 2026-07-30에 이 방식으로 로케일 보드에서 7건이 나왔다.
> 사람이 잘 안 보는 자리(twitter 태그·aria-label·숫자 포맷·회장명)에서 나왔다.

### 5-3. 기계 점검

```bash
npm run check:intl-links   # 대상 실존 + 언어경로
npm run build              # sitemap 갱신 + patch-html-lang 자동 실행
```

렌더 HTML을 **직접 열어** 확인: 한글 누수 0 · 숫자 포맷 · 실검색어 렌더.

## 6. Phase 4 — 배선과 배포

### 6-1. blogLink는 자동이다 (추가 작업 없음)

`lib/posts-<locale>/`에 글을 넣고 `index.ts`에 등록하면 **끝이다.**
`resolveBlogLinks`가 존재를 확인해 보드 카드에 📖 링크를 자동으로 띄운다.

대회에 `blogLink`가 아직 없으면 `lib/tournaments.ts`에 한 줄만 추가한다.
ko판이 없어도 안전하다 — ko는 존재 검사에서 걸러 링크를 조용히 숨긴다.

### 6-2. 배포

```bash
git add . && git commit && git push     # Vercel 자동 배포
```

⚠️ 빌드 파이프라인을 건드렸다면 **배포 후 라이브 응답을 curl로 직접 확인.**
`vercel.json`의 `buildCommand`가 `npm run build`를 우회하므로 npm 훅은 프로덕션에서 안 돈다.

### 6-3. 기록

`WORKLOG.md` 최상단 + `session-handoff.md`.
배운 것은 **§3의 표대로 해당 파일에** append (교정 사례는 정본 = `translation-terms-<lang>.md`).
