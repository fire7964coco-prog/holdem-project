# OG/트위터 카드 감사 — 서버 metadata ↔ 렌더 후 DOM (2026-09-20)

> 발단: 계산기 브리프 §5 「🟠 클라이언트 `<SEO>`가 `og:title`을 서버 `openGraph.title`과 다른 값으로
> 덮어쓴다 — en·ja·zh 공통」. **실측해 보니 5곳이 아니라 20/20이었고, 원인도 둘이었다.**
> 방법 = 같은 URL을 **JS 끈 컨텍스트**(서버 HTML)와 **켠 컨텍스트**(렌더 후 DOM)로 각각 열어 비교.

## 0. 결론

**og는 서버 전용 영역이다.** 클라이언트가 런타임에 고치는 것은 ① 소셜 스크래퍼에겐 **영원히 안 보이고**
② 구글에겐 **서버와 다른 값**을 보여 줄 뿐이다. → 서버에 채우고 클라이언트는 손을 뗐다.

## 1. 실측 — 20개 라우트 전부 덮어쓰고 있었다

| 클래스 | 증상 | 해당 |
|---|---|---|
| **① 서버 og 부재** | 서버 og:title = «홀덤마스터 — 텍사스 홀덤 완벽 가이드» · og:url = **홈** | `/ranking` `/glossary` `/hands` `/strategy` `/hand-chart` `/quiz` `/pub` `/rules` `/rules/seven-card-stud` `/rules/texas-holdem` |
| **① -b 부모 layout 누수** | `app/blog/layout.tsx`의 **블로그 카드**를 물려받음 | `/blog/roadmap` |
| **② 의도된 서버 값을 덮어씀** | 서버가 카드용 짧은 제목을 일부러 따로 두는데 페이지 제목으로 덮임 | 계산기 랜딩 12 · `/en/ranking` · `/en/glossary` |

🔴 **①은 2026-08-02 사고의 «안 고쳐진 축»이다.** 그때 `title`·`description`·`canonical`은 고쳤지만
**`openGraph`는 손대지 않았다.** `/rules/texas-holdem`은 서버 `<title>`·`description`까지 홈 값이었다.

🔴 **왜 그동안 안 보였나**: 클라이언트 `<SEO>`가 런타임에 «고쳐» 놓아서, 브라우저로 열어 보면 정상으로
보였다. **JS를 꺼야 보이는 결함**이다 — 게이트 `check:seo-sync`도 이 축(og)은 안 봤다.

## 2. 왜 클라이언트 갱신이 무의미한가

- **카카오톡·페이스북·트위터 스크래퍼는 JS를 돌리지 않는다.** 서버 HTML만 읽는다.
  → 공유 카드는 **항상 서버 값**으로 나갔다. 클라이언트가 고친 값은 아무도 못 봤다.
- **구글은 렌더한다.** 그래서 구글만 서버와 다른 값을 봤다 — 일치시킬 이유가 없는 불일치다.
- SPA 이동 뒤 og가 이전 페이지 값으로 남는 것은 **무해하다**: 스크래퍼는 URL을 새로 받아
  서버 HTML을 읽지, 남의 브라우저 히스토리를 따라오지 않는다.

## 3. 처방

1. **`lib/page-metadata.ts` 신설** — `socialMeta({ title, description, path })`가 `openGraph`+`twitter`를
   한 번에 만든다. 🔴 **Next metadata는 얕은 병합**이라 두 함정이 동시에 있다:
   **안 적으면** 루트의 홈 카드가 나가고, **적으면** 이번엔 `images`가 상속되지 않아 카드가 빈다.
   헬퍼가 둘 다 닫는다.
2. **클래스 ① 11개 라우트**에 `...socialMeta(...)` 적용. 제목·설명은 **상수로 올려** og와 한 문자열을 쓴다.
3. **`images` 누락 3곳** 보강 — `/calculator`(ko · `twitter` 키 자체가 없었다) · `/en` · `/en/solver`.
4. **`components/seo.tsx`에서 og:title·og:description·og:url 갱신 제거.** `document.title`·`description`·
   `canonical`만 남겼다(SPA 이동 표시 보정이라는 원래 목적).
5. **`lib/calculator-alternates.ts`에 `x-default` 추가** — `/en/calculator`를 지목(도구 용어가 가장 국제적).

## 4. 🔴 게이트를 같이 고쳤다 — 내 리팩터가 게이트를 깼다

제목·설명을 상수로 올리자 `check:seo-sync`가 **8건을 오탐**했다(«서버에 title이 없다»).
게이트의 `serverMeta()`가 `title: "리터럴"`만 읽고 **`title: TITLE`(상수 참조)을 못 읽었기** 때문이다.

🔴 **고칠 것은 코드가 아니라 게이트였다** — 게이트 자신이 `holdem-practice`를 「모범 사례: 상수를
import해 두 곳이 같은 문자열을 쓴다」로 칭찬하고 있었다. 리터럴을 두 번 적는 쪽이 드리프트를 만든다.

**그리고 첫 수정에 우선순위 버그가 있었다**: 리터럴 스캔을 먼저 두었더니, metadata가 상수를 가리키는
순간 **파일 뒤쪽 `jsonLd`의 `description`을 metadata 것으로 잘못 집었다**(`/ranking`이 사이트 목록
설명을 물고 왔다). → **상수 해석을 리터럴 스캔보다 먼저**로 바꾸고 **회귀 셀프테스트를 박았다.**

셀프테스트 14 → **20/20**. 새 케이스: 상수 title·description · `{absolute: CONST}` ·
**보간 템플릿은 안 푼다**(정적으로 값을 모른다 → 사람이 판정) · 미정의 상수는 null ·
**상수가 jsonLd 리터럴보다 우선**.

## 6. 같은 회차에서 닫은 사전 부채 (브리프 §5)

- 🔴 **오버카드 정의** «not on board» → «보드의 **모든** 카드보다 높은 2장» (EN·es·ja·zh·zh-hant).
  보드가 A-K-Q일 때 7·2도 «보드에 없는» 카드지만 오버카드가 아니고 **×3=6 아웃츠 산술이 성립하지 않는다.**
- 🔴 **×2 규칙의 오차 방향** — 「1–2 포인트 낮다」는 5~11 아웃츠에서만 참이다.
  **검산**: 부족분 = `N/46 − 0.02N` 으로 **아웃츠에 비례해 커진다** — 9 아웃츠 `19.57−18=1.57` ·
  15 아웃츠 `32.61−30=2.61`. → 「아웃츠가 많을수록 더 모자란다(9→1.6 · 15→2.6)」로 통일(EN·ja·zh·zh-hant).
- 🪶 EN `A3s` «Bottom of the suited aces» — **같은 표에 A2s가 있어 거짓**이었다 → 문구 교체.
- 🪶 EN `outs.exactNote` «The big number» — «big»이 **활자 크기인지 값 크기인지** 갈린다.
  값으로 읽으면 거짓이다(15 아웃츠에서 Rule of 4는 60%, 정확값 54.1% → **규칙 쪽이 더 크다**).
  → «The figure in large type is the exact one»으로 못 박고, 로케일 번역 축도 주석에 남겼다.
