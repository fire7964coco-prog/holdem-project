## 1. ★이 시리즈의 성격 — 경험담을 넣지 않는다

**2026-08-08 사장님 결정.** CLAUDE.md §8은 "모든 포스트에 실제 경험담 필수"를 요구하지만
**이 시리즈는 예외다.**

> 사장님: *"이건 일반적인 포스팅이 아니라 GTO 솔버의 13가지 상황을 하나씩 설명해주는
> 포스팅이라서 굳이 개인 경험이 안 들어가도 되지 않을까. 오히려 구글 AI 답변을 하기 어려운
> 고급 계산이기 때문에 오히려 오피셜하게 객관적 정보 제공은 어떨까."*

**왜 예외가 정당한가**: §8의 취지는 «AI가 지어낸 일반론 글»을 막는 것이다. 이 13편은 성격이
정반대다 — **우리가 만든 솔버로 직접 계산한 1차 데이터**이고, 구글 AI 답변이 만들어낼 수 없는
구체적 수치가 본체다. E-E-A-T의 Experience는 "직접 계산해서 얻었다"로 이미 충족된다.

**대신 «재현 가능성»이 출처를 대신한다. 이 셋은 매 편 필수다:**

1. **계산 조건 표** — 프리플랍 액션 · 레인지 · 플랍 · 팟/스택 · 벳 사이즈 · **레이크 미고려**
2. **0.1bb 단위 안내** — 솔버 화면의 「팟 55」는 5.5bb, 「EV 20.9」는 2.09bb
3. **「직접 확인해보기」 절** — 교육 예제 이름을 정확히 적어 원클릭 재현시킨다

## 2. 글 구조 (1편에서 확립)

```
히어로 이미지(솔버 화면)
도입 — 독자의 질문/오해로 시작 ("탑 페어인데 먼저 벳하는 게 맞을까요?")
:::stripe  스팟 / 플랍 / 팟·스택 / 결론 4줄
> **바로 답**   ← 2~4줄 자기완결 단락
## 이 수치는 어떤 조건에서 나왔나요?   ← 계산 조건 표 + 0.1bb 안내
## <핵심 수치>가 정확히 얼마인가요?    ← 액션 빈도 표 + 두 번째 이미지(액션 대비)
## <독자의 반문>이 맞나요?             ← "탑 페어인데도 체크가 맞나요?"
## 왜 <그 결과>가 나오나요?            ← 레인지 구성 표
## 에퀴티/EQR 해석
## 그럼 상대(IP)는 어떻게 쳐야 하나요?
## 실전에서 무엇을 바꾸면 되나요?      ← 불릿 3개
## 직접 확인해보기                     ← 교육 예제 CTA
**Q. …**  (빈 줄)  A. …   × 4문항
```

- **질문형 H2 70% 이상**(§14-A). 1편은 8개 중 7개가 질문형이다.
- 어투는 **존댓말 + 평서체**(본체 톤). 반말 금지 — 참고했던 포커고수 글은 커뮤니티 반말이지만
  본체는 「습니다/입니다」다(945/913회 대 「해요」 41회).
- 포커고수 글에서 **가져온 것은 «전개»뿐**이다: ① 독자의 오해를 먼저 꺼내 반박 ② 같은 스팟에서
  조건을 바꿔 대비 ③ 개념을 그림으로 증명.

## 3. 🔴 이미지 — 반드시 알아야 할 함정

**파일명의 `_ip` / `_oop`는 «플레이어 구분이 아니다».**

7개 스팟의 짝을 픽셀 비교했더니 **전부 같은 노드**였다(차이 0.2~0.9%). 다른 것은
**하이라이트된 액션**뿐이다. 26장 전부 **OOP 전략 화면**이고 **IP 대응 캡처는 한 장도 없다.**

- ❌ "IP(BTN)의 대응은 이렇습니다" + `_ip` 이미지 → **§13 사실오류**
- ✅ 「체크로 가는 핸드(초록)」 vs 「벳으로 가는 핸드(노랑)」 **액션 대비**로 쓴다

**새 편을 쓸 때 그 스팟의 이미지 2장을 반드시 Read로 열어**, 좌상단 패널의 플레이어·액션 빈도와
매트릭스 색을 확인하고 캡션을 붙여라. 파일명을 믿지 마라.

크롭은 이미 끝났다(`scripts/convert-solver-captures.mjs`, 1600×900 → 875×865).
원본을 그대로 쓰면 안 되는 이유: 렌더러가 **w=750으로 줄여 보내** 매트릭스 글자가 뭉개진다.

## 4-A. ★진행 방식 (2026-08-08 사장님 결정)

| 항목 | 결정 |
|---|---|
| **한 세션 분량** | **5편**. 그다음은 새 세션(`/clear`)에서 다시 5편 → 마지막 2편 |
| **적대적 검수** | **편당 1회 필수.** ★**Agent 툴(서브에이전트)로 돌린다** — 사장님이 명시적으로 허가했다. 검수 리포트가 본 세션 컨텍스트를 안 먹으므로 5편이 안정적으로 들어간다 |
| **배포 단위** | **묶어서.** 편별로 올리지 말고 5편을 모아 한 번에 빌드·배포한다(시리즈 내부링크를 함께 엮기 위해) |
| **자율 모드** | **사장님 확인 없이 판단해서 배포까지 진행한다.** 다만 §13 검산과 적대적 검수는 건너뛰지 않는다 |

**적대적 검수 프롬프트에 반드시 넣을 것** (메모리 `adversarial-review-lens-diversity`):
- ★**렌즈를 갈라라** — 페르소나 수보다 렌즈 다양성이 성과를 낸다.
  이 시리즈에 맞는 렌즈: ①**검산**(수치 정합·EQR 역산) ②**실전 딜러/플레이어**(유해 조언 여부)
  ③**교열**(직답 삽입이 만든 축어 중복) ④**SEO**(키워드·직답 구조)
- 프롬프트에 **"의도적 제외 목록"과 확신도 표기**를 요구할 것
- ★★**지적 반영 후 2차 교열 패스 필수** — 수정이 새 모순을 만든다
- 값어치는 «한 렌즈만 잡은 항목»에서 나온다

## 5. 편당 체크리스트

```
1. 원본 md 읽기 → 수치·해석 파악
2. lib/posts/a-high-board-cbet.ts 복사 → 새 slug로 구조 채우기
3. 이미지 2장 Read로 육안 확인 → 정확한 캡션
4. ★§13 손 검산 — 게이트가 이 시리즈를 «미검사»로 흘린다(커버리지 "카드 문단 0개")
     팟 = 오픈 + 콜 + SB   /   유효스택 = 100 - 오픈
     액션 빈도 합 = 100%   /   EV 합 = 팟(0.1bb 단위)
     EQR 역산 = EV ÷ (에퀴티 × 팟)  → 글의 EQR과 ±0.3%p 안에 들어와야 한다
     보드 무늬(레인보우/투톤/몬톤) 표기가 실제 카드와 맞는지
5. lib/posts/index.ts 에 import + NEW_POSTS 앞에 추가
6. npm run audit:hard -- --slug=<slug>   → 🔴 0건
7. 적대적 검수 (사장님 지시: 편당 1회)
8. npm run build → canonical:check
9. 커밋·배포
```

**§13 검산을 건너뛰지 마라.** 게이트는 이 시리즈의 카드 표기를 인식하지 못해 0건으로 통과시킨다.
그 0건은 «검증»이 아니라 «미검사»다(CLAUDE.md §14-A 9).
