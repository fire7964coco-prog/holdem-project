## 0. 원칙

1. **도구는 전부 로그인 없이 쓴다.** 글·도구 일부를 가입 뒤로 숨기지 않는다(구글이 못 읽고, 첫 방문자가 나간다).
2. **가입의 이유 = 쌓인 기록을 잃지 않는 것.** 로그인 안 하면 이 브라우저에만, 로그인하면 계정에 남아 폰·PC 어디서나 보인다.
3. **권유는 기록이 생긴 사람에게만, 한 줄로.** 팝업·반복 요청·보상 없음(후기창 설계 §11과 같은 원칙).
4. **기록은 본인만 본다.** 공개 순위표·남과 비교 없음.

## 2. 화면

### 2-1. «내 기록» — 커뮤니티 프로필 탭 안
- 위치: 프로필 탭(`?tab=profile`)의 프로필 카드 바로 아래, «내 글» 위. 따로 페이지를 만들지 않는다(로그인·프로필이 이미 거기 있다).
- 카드 3장(기록이 없는 카드는 «아직 기록이 없어요 — [도구 열기]» 한 줄로 접는다):

| 카드 | 보여 줄 숫자 | 버튼 |
|---|---|---|
| 🎯 승률 퀴즈 | 푼 판 수 · 평균 오차(%p) · 콜/폴드 판정 맞힘률 · 최근 7일 판 수 | 퀴즈 계속하기 → `/win-rate-quiz` |
| 🧠 GTO 트레이너 | 푼 문제 수 · 평균 EV 손실(bb) · 최선 선택 비율 · 종류별(SRP·3벳 팟·블라인드) | 트레이너 열기 → 솔버 |
| 📁 솔버 저장 목록 | 레인지 N개 · 벳 설정 N개 | 솔버 열기 |

- 로그인 안 한 사람의 프로필 탭: 지금의 «로그인이 필요해요» 카드 문구에 «기록을 계정에 남길 수 있어요» 한 줄을 더한다.

### 2-2. 도구 안 권유 한 줄
- 승률 시뮬레이터: 퀴즈 누적 줄 아래, **누적 판 수 1 이상 + 로그인 안 함**일 때만
  «로그인하면 이 기록이 계정에 남아 폰·PC 어디서나 볼 수 있어요 [로그인]». 로그인 뒤 돌아오면 원래 화면(`loginHref(next)`).
- 솔버: 솔버 설계안 §3 그대로(저장 항목 1개 이상일 때만).

## 3. 데이터

### 3-1. 새 표 `win_rate_quiz_hands` — 퀴즈 1판 = 1행
| 열 | 뜻 |
|---|---|
| `user_id` | 본인 |
| `client_id` | 기기에서 만든 고유값(같은 판을 두 번 올려도 1행 · `unique(user_id, client_id)`) |
| `table_size` · `players` | 6/9 · 2~6 |
| `guesses` · `err_sum` | 짐작 횟수 · 오차 합(%p) — 평균 오차 = err_sum ÷ guesses |
| `decisions` · `hits` | 콜/폴드를 고른 횟수 · 팟오즈 판정과 맞은 횟수 |
| `points` | 그 판 점수 합 |
| `played_at` | 기기 시각 · `created_at` = 서버 시각 |

- 카드·보드는 저장하지 않는다(용량·필요 없음). 핸드 복기 노트(§9)를 하면 그때 따로 표를 만든다.
- 상한: 사용자당 20,000행(하루 50판 × 1년 남짓). 넘으면 저장만 실패하고 화면은 그대로.

### 3-2. 쓰는 길 — **앱이 Supabase에 직접 쓰기 + 본인만 RLS** (S-067 판정 겸)
- 트레이너 기록(`trainer_attempts`)과 같은 방식. 본인만 보는 사적 기록이라 공개 글(후기창 §11 «직접 쓰기 안 함»)과 성격이 다르다 → **솔버 저장 목록(①)도 같은 판정.**
- 로그인 안 함: 이 브라우저(localStorage)에 판 기록을 쌓는다 — 지금의 «페이지에 있는 동안만»에서 «이 브라우저에 계속»으로 올린다.
- 로그인함: 판이 끝날 때 1행 저장. **처음 로그인하면 브라우저에 쌓인 판을 한 번에 올린다**(client_id로 중복 없음 · 트레이너와 같은 방식).
- 실패해도 화면은 막지 않는다(브라우저 기록은 남는다 · 다음 방문 때 다시 올린다).

### 3-3. 솔버 표 `solver_saved_items` — S-067 SQL 검토 결과
- 그대로 받는 것: 4단 그룹 열 · 지운 표시 · 서버 시각 트리거 · 본인 RLS 4정책 · `value` 20,000바이트 상한.
- **고칠 것 1 — 상한이 지운 표시까지 센다.** 지우고 저장하기를 오래 반복하면 실제 목록이 적어도 막힌다
  → «살아 있는 행 1,000 + 지운 표시 포함 전체 3,000»으로 나눈다(전체 상한은 무한 증식 방지용). 솔버에 «지운 표시를 오래 들고 있지 않는 정리» 필요 여부를 묻는다.
- 고칠 것 2(경미) — 상한 트리거가 `insert`만 본다. 지운 표시를 되살리는 `update`(deleted_at → null)도 살아 있는 행 상한을 넘길 수 있다 → update에도 같은 검사.

### 3-4. 지우기
- 계정 삭제 = 세 표 모두 `on delete cascade`로 같이 지워진다.
- «내 기록» 카드마다 «이 기록 지우기»(확인 한 번) — 개인정보 처리방침의 «파기» 문장과 맞춘다.

## 5. 문구·언어
- «내 기록»은 프로필 탭이 있는 **전 로케일**에 뜬다 → 새 키 약 15개를 프로필 탭 로케일 전부에 넣는다(카드 이름·숫자 라벨·빈 상태·지우기 확인).
