# 다국어 포스팅 작성 — 실행 문서 (이 파일 하나로 작성 가능)

> **사용법**: 다국어 포스팅 작업을 시작할 때 이 파일을 붙여넣고 «이대로 진행»이라고 지시하면 됩니다.
>
> **이 문서의 자리**: `docs/translation-spec.md`가 **파이프라인·배선·조립·QA 절차**를 정의합니다.
> 이 문서는 그중 **«글을 실제로 쓰는 단계»만** 실행 가능한 형태로 떼어낸 것입니다.
> 둘이 충돌하면 `translation-spec.md`가 우선입니다. 신규 로케일 배선(⓪ 체크리스트)·조립·
> 하드게이트·적대적 QA는 그쪽을 보세요.
>
> **왜 따로 있나**: 스펙에 «서브에이전트 프롬프트에 이 마인드셋을 항상 포함할 것»이라고
> 적혀 있지만, 매번 137줄 스펙을 사람이 다시 요약해 프롬프트를 조립하면 조금씩 샙니다.
> 그 새는 부분이 검수 오류로 나옵니다. **요약하지 말고 §2를 그대로 붙여 쓰세요.**

---

## 1. 작성 «전» 게이트 — 자료 없이 쓰지 않는다

작성 서브에이전트는 **본문을 쓰기 전에 아래를 먼저 제출**합니다. 통과해야 본문 착수.

```
### 리서치 산출물 (본문 작성 전 제출)

1) 롱테일 키워드 — 대상 언어로 실제 검색해 확인한 것 5개 이상
   | 검색어 | 어디서 확인했나 | 이 글의 어느 절이 받나 |

2) 현지 SERP 상위 3편 — 무엇을 다루고 무엇을 빠뜨렸나
   | URL | 다루는 각도 | 우리가 더 줄 수 있는 것 |

3) 용어 확정표 — 이 글에 나오는 포커 용어 전부
   | 개념 | 현지 표기 | 출처 URL | 출처 등급(§3) |
   ※ 출처 URL이 빈 줄은 만들지 않는다. 못 찾으면 «영어 그대로»로 적는다.

4) 이 시장 특유의 맥락 — 규제·통화·플랫폼·문화 레퍼런스 중 본문에 반영할 것
```

> 자료 수집을 «권장»으로 두면 글부터 씁니다. 산출물을 먼저 내게 하면 건너뛸 수가 없습니다.

## 2. 작성 프롬프트 — 이 블록을 그대로 붙여 씁니다

> `{{언어}}` `{{국가}}` `{{슬러그}}`만 바꿉니다. **요약해서 다시 쓰지 마세요.**

```
당신은 {{국가}}에서 나고 자란 {{언어}} 원어민이자, 그 나라 포커 씬에서 수십 년 뛴
텍사스 홀덤 전문가입니다. 동시에 그 언어로 글을 써 온 필자입니다.

## 이 작업의 본질 — 이것부터 이해하고 시작하세요
이건 **번역이 아닙니다.** 영어 원문을 얼마나 충실히 옮겼는지는 평가 기준이 아닙니다.

원문(lib/posts-en/{{슬러그}}.ts)을 읽고 **내용을 완전히 파악한 뒤**, 그 내용을
**{{국가}} 독자에게 당신이 직접 설명하듯** 새로 씁니다. 원래부터 {{언어}}로 쓰인 글처럼
읽혀야 합니다. 제목·훅·예시·비유·문단 흐름·검색 각도를 현지 기준으로 다시 잡으세요.

판단 기준은 «원문과 얼마나 같은가»가 아니라
**«이 언어 원어민이 읽을 때 자연스럽고, 이 시장 검색에 맞는가»**입니다.

## 절대 바꾸지 않는 것 — 여기만은 그대로 복사
- 숫자·확률·산수 — 계산 결과가 달라지면 치명적입니다
- 카드 표기 (A♠ K♥ 등)
- slug — hreflang이 걸려 있습니다
- category 값 — 표준 필라값
- 마크다운 구조: 표, ==하이라이트==, :::readnext, FAQ의 **Q.**/A. 리터럴,
  HTML 카드, 이미지 경로(alt만 번역), tldr·layout 필드

## 쓰기 전에 반드시
1. 리서치 산출물을 먼저 제출하세요 (통과 후 본문 작성)
   [이 문서 §1 표를 여기 붙여넣기]

   ⚠ 다른 현지어 파일을 베끼지 마세요 (특히 id↔ms, ru↔uk)
```

## 3. 용어 출처 등급 — 아무 사이트나 근거로 쓰지 않는다

| 등급 | 종류 | 신뢰도 |
|---|---|---|
| **1급** | 제품사 **공식 현지화** 페이지 (그 회사가 돈 들여 현지화한 것) | 높음 |
| **2급** | **현지인이 서로 쓴 글** — 포럼 스레드·커뮤니티·현지 매체 기사 | 높음 (번역될 이유가 없음) |
| **3급** | 어필리에이트 용어집·SEO 사이트 | ⚠ **기계번역·과잉번역 위험** |

**규칙**

1. **3급 단독 출처는 채택 금지.** 최소 2곳, 그중 하나는 1급이나 2급이어야 합니다.
2. **2급(포럼·커뮤니티)을 결정적 근거로.** 플레이어끼리 주고받은 글은 번역본일 수 없습니다.
3. **용어집에만 있고 «실제로 그 단어를 쓴 문장»이 검색되지 않으면 조어로 보고 버립니다.**
4. **애매하면 영어를 그대로.** 포커는 영어가 공용어라 영어 유지가 거의 항상 안전합니다.
5. **용어표에 출처 URL 없는 줄을 만들지 않습니다.**

**이 규칙이 생긴 이유 — 실제 사고 2건** (솔버 앱 3개 언어 761문구 원어민 검수, 2026-08)

- **`Batalla de ciegas`** (블라인드전, 스페인어) — 리서치 파일에서 **출처 URL 없이
  «관용 표현»이라고만** 적힌 유일한 항목이었습니다. 원어민 검수 결과 **실사용례 0건**,
  표준은 `guerra de ciegas`였습니다.
  → **출처가 적힌 용어는 스페인어·일본어 통틀어 100% 통과했고, 출처 없던 하나가
  정확히 틀렸습니다.**
- **`Atrapa-bluffs`** (블러프캐처) — 3급 용어집에서 가져왔는데 «매체가 안 쓰는 조어» 판정.
  그런데 **같은 용어집에서 가져온 영어 유지 항목**(`Squeeze`·`Top pair`)은 멀쩡했습니다.
  → **위험한 건 그 사이트가 «번역을 더 열심히 한» 항목입니다.** 원어민 매체는 영어를
  그대로 쓰는데 용어집만 굳이 현지어 단어를 지어낸 자리 — 거기가 기계번역이 튀어나오는
  지점입니다.

## 4. 제출 전 자가검사 — 검수에서 반복되는 것만 모았습니다

작성자가 **제출 전에 스스로** 돌립니다. 검수자가 잡기 전에 잡는 게 목적입니다.

```
□ 숫자·확률·산수를 원문과 한 줄씩 대조했다 (불변 항목)
□ 카드 표기(A♠ 등)가 원문 그대로다
□ 숫자 표기가 이 언어 관습에 맞다
   · 유럽식(es·pt·de·id·vi·it·ru·pl·uk·ro): 1.326 / 2,5
   · 영어식(en·zh·ar·ms·th·hi·bn·fil·he·sw·fa): 1,326 / 2.5
   · fr: 천단위 NBSP + 소수점 콤마
   · 비라틴 숫자(fa ۰-۹ · bn ০-৯ · hi ०-९) 잔류 0건
□ 용어표의 모든 줄에 출처 URL이 있다 (없으면 영어 그대로로 바꿨다)
□ 같은 개념을 글 안에서 두 가지 이름으로 부르지 않았다
□ 다른 언어 잔재가 없다 (영어·한국어·스페인어, ru↔uk·ar↔he 오염)
□ 내부링크가 전부 /<lang>/blog/<slug> 이고, 허용 슬러그 목록 안에만 있다
   (목록 밖 대상: 본문은 링크만 제거하고 텍스트 남김, readnext/Related는 줄 통째 삭제)
□ desc ≤ 160자 · seoTitle이 현지 SERP에서 안 잘린다
□ FAQ의 **Q.**/A. 리터럴이 살아 있다 (스키마)
□ slug·category가 원문과 같다
□ masterUpdated에 EN 원문의 updated 값을 넣었다
□ 제목과 첫 문단을 소리 내어 읽었을 때 «번역체»가 아니다
```

### 놓치기 쉬운 함정 — 개념 범위가 어긋나는 경우

번역이 «맞는데»도 틀리는 경우가 있습니다. **원문 단어와 현지 단어의 포함 범위가 다를 때**입니다.

실제 사례: 영어 `Trips`는 좁은 뜻(보드 페어 + 홀카드 1장)인데, 그 칸에 **셋(포켓페어 + 보드
1장)까지** 들어가고 있었습니다. 일본어 `トリップス`도 똑같이 좁아서 같은 문제가 났습니다.
반면 한국어 `트리플`과 스페인어 `Trío`는 총칭이라 문제가 없었습니다 — **언어마다 답이 달랐습니다.**

확인법: 그 단어가 **원문이 가리키는 범위를 전부 덮는지** 현지 자료로 확인합니다.
못 덮으면 범위를 넓히거나(`Set/Trips`) 다른 단어를 씁니다(`スリーカード`).

## 5. 검수가 매번 새 오류를 찾을 때 — 정상인 지점과 아닌 지점

- **정상**: 문장 다듬기, 더 나은 현지 표현, 검색 각도 개선. 이건 계속 나옵니다 —
  품질이 올라간다는 뜻입니다.
- **비정상 = 고쳐야 할 신호**: **같은 유형**이 언어를 바꿔도 반복될 때.
  숫자 표기·용어 흔들림·내부링크·다른 언어 잔재가 대표적입니다.

**같은 유형이 3번 이상 반복되면 사람이 아니라 기계로 옮기세요.**
이미 `scripts/check-intl-links.mjs`, `npm run check:stale`, 숫자표기 grep이 있습니다.
검수 리포트에서 반복 유형이 보일 때마다 **스크립트를 하나씩 늘리는 것**이
«검수할 때마다 오류가 나온다»를 끊는 유일한 방법입니다.

> 참고 실측: 솔버 앱 검수에서 **원어민 검토자 3명이 전부 놓친** 스페인어 복수형 버그 5건을
> **언어 간 자리표시자 대조 스크립트**가 잡았습니다. 사람이 잘 잡는 것과 기계가 잘 잡는 것이
> 다릅니다. 둘 다 필요합니다.
