## 1. 판정 기준 (추측 아님 — 렌더러 코드가 진실)

`lib/intl-blog-page.tsx`가 FAQ를 뽑는 **유일한 정규식**이다:

```
/\*\*Q\.\s*([^*\n]+)\*\*\n\n?A\.\s*([^\n]+)/g      +  faqItems.length >= 2
```

따라서 **넷 다** 지켜야 리치결과가 붙는다:

1. 질문이 `**Q. …**` 꼴 — **라틴 `Q.`** 이고, 질문 안에 `*` 금지
2. 그다음 줄바꿈(빈 줄은 있어도 없어도 된다)
3. 답이 **라틴 `A. `로 시작하고 한 줄**
4. 그렇게 만들어진 짝이 **2개 이상**

`npm run check:faq-schema`가 매 실행 이 정규식을 **렌더러 소스에서 다시 읽어 대조**한다.
렌더러가 바뀌면 게이트가 먼저 빨간불이 된다(판정이 조용히 거짓이 되는 걸 막는 장치).

## 3. 왜 지금까지 안 잡혔나 — 검사 자체가 없었다

- `audit:hard --schema`는 **`.next/server/app/blog/` 만** 본다 = **한국어 전용**.
  다국어 산출물은 `.next/server/app/<locale>/blog/`에 있는데 이 경로를 보는 코드가 없었다.
- `check-de-style.mjs`의 D6은 **de만** 본다(2026-08-10 Session 0 신설).
- 나머지 23개 로케일은 **원리상 미검사**였다.

→ [[review-mechanize-not-repeat]]의 「‘없다’ 보고 전 탐지 방법부터 의심하라」가 또 맞았다.
   hreflang(08-10 (5))과 **같은 병**이다: 검사가 있다고 «믿고» 있었을 뿐 없었다.

### 🔴 KO와 다국어는 «지원 패턴 수»가 다르다 — 이게 함정의 근원이다

| | `**Q. …**` + `A. …` | `### Q1. …` |
|---|---|---|
| `app/blog/[slug]/page.tsx` (KO) | ✅ | ✅ |
| `lib/intl-blog-page.tsx` (다국어) | ✅ | ❌ |

**KO 글을 그대로 옮기며 `### Q1.` 형식을 쓰면 조용히 스키마가 사라진다.** 게이트가 이걸 이름으로 진단한다.

### 🔴 3번 착수 시 반드시 지킬 것 (EN 수정 때 실제로 사고가 났다)

**PowerShell에서 `node -e`로 파일을 고치지 마라** — CLAUDE.md §16이 경고하는 그것이다.
`t.replace(/(\n\s*updated:\s*)"[^"]+"/, '$1"2026-08-10"')` 를 `node -e "…"` 로 돌렸더니
**PowerShell이 `$1`을 «빈 변수»로 먹어** 프런트매터가 `date: "2026-06-10",\x222026-08-10",` 로 뭉개졌고
**빌드가 깨졌다**(에러가 webpack 번들 덤프로 나와 원인 파악에만 시간이 들었다).
→ **치환은 `.mjs` 파일로 작성해 실행한다.** 그리고 CRLF 파일은 `\n` 기준 치환이 **CR을 남긴다** —
   줄끝을 파일에서 읽어 그대로 복원하라(`const eol = t.includes('\r\n') ? '\r\n' : '\n'`).

**드라이런 → 기대 건수 대조 → `--apply`** 순서도 지켜라. 이번 EN 수정은 그 절차를 지킨 부분
(`A.` 접두 8곳·`###` 전환 12곳)에서는 **한 건도 어긋나지 않았다.** 사고는 절차를 건너뛴 한 줄에서 났다.
