```ts

  slug: 'holdem-example',
  title: '제목 40자 이하',

};

```

### Step 2 — index.ts에 import 추가
`lib/posts/index.ts`의 `NEW_POSTS` 배열 앞에 추가.

### Step 3 — 이미지
- 경로: `public/images/[slug]-hero.webp`
- 규격: 1200×675, webp quality 65, **60KB 이하**
- 히어로 이미지: `priority={true}` 필수

### Step 4 — 내부링크
- 새 포스트 본문에 관련 기존 포스트 링크 최소 3개
- 기존 관련 포스트에도 새 포스트로 역링크 추가

### Step 5 — ★검수 (발행 전 필수)
**`REVIEW-PROTOCOL.md`를 통독하고 3층 게이트를 그대로 적용한다.** 신규 포스팅도 예외 없다.
```bash
npm run audit:hard -- --slug=[slug]   # 🔴 0건까지
npm run audit:hard -- --uncovered --slug=[slug]   # 기계가 못 본 카드 문단 직접 검산
```
그다음 적대적 렌즈(D·F유형)를 돌린다 — 게이트가 초록이어도 이건 별도다.

### Step 6 — 빌드 & 배포
```bash
npm run build  # 빌드 성공 + sitemap 갱신 확인
git add . && git commit -m "feat: 새 포스트 [slug]" && git push
```

## 14. 검수 체크리스트 (현재 가장 자주 하는 작업)

> ### 🔴 검수 요청을 받으면 **`REVIEW-PROTOCOL.md`(레포 루트)를 먼저 통독하고 그대로 따른다.**
> 신규 포스팅 직후 검수·기존 글 검수·경화·번역본 검수 **전부** 그 파일이 본체다.
> 3층 게이트(① 기계 `npm run audit:hard` → ② 미판정 문단 육안 검산 `--uncovered` →
> ③ 적대적 렌즈 4종)와 그 근거·함정·프롬프트 장치가 거기 다 있다.
> 아래 목록은 그 파일의 **요약**일 뿐이다 — 상충하면 `REVIEW-PROTOCOL.md`가 우선한다.

특정 글을 검수하라는 요청을 받으면 아래를 순서대로 점검·수정한다.

1. **사실 정확성** (§13) — 포커 핸드 예시, 전략 수치, 토너먼트 정보(운영사·날짜·바이인), 룰 설명
2. **trailing slash** — 내부 링크가 `/blog/x/`로 끝나면 301 발생 → `/blog/x`로 수정
   - 점검: `grep -n "/blog/[^)\"']*/[\")]"` 또는 Grep으로 `/" 패턴` 검색
3. **링크 유효성** — 참조한 slug가 실제 존재하는지 (`lib/posts.ts` + `lib/posts/` + `lib/posts-en/`에서 확인)
4. **이미지 점검**:
   - 깨진/플레이스홀더 이미지: **1KB 안팎 webp = 빈 플레이스홀더** (내용 없음) → 새로 제작 필요
   - 용량 초과: 60KB(복잡한 인포그래픽 80KB) 초과 → 재압축 (§15)
   - alt 텍스트: 구체적 상황 묘사인지 (키워드 나열 금지)
4. **`updated` 날짜** — 글 수정 시 `updated`(또는 `dateModified`)를 오늘 날짜로 갱신 (sitemap lastmod 반영)
5. **메타** — seoTitle/desc 길이·훅 (§8)

### 검수 우선순위
GSC 노출 높은 글 → 전략 글(핸드 예시 많아 오류 위험 큼) → 토너먼트 가이드(날짜·운영사 정보 노후화)

## 14-A. ★ 경화(hardening) 작업 표준 (2026-07-30 사용자 지시로 확립)

> 기존 글을 클러스터 단위로 끌어올리는 작업의 고정 규격. **신규 발행(§6)과는 다른 절차다.**
> 신규 발행의 "경쟁 SERP Top10 분석"은 **첫 포스팅용**이며 경화에는 요구하지 않는다.

1. **`> **바로 답**` 블록** — 상단 `:::stripe` 아래. **2~4줄 자기완결 단락**(한 문장 강박 금지, 구글 AI 답변처럼 직답).
   기존 `> **한 줄 답**` · `> **한 줄 정리**` · `> **한 줄 요약**`은 전부 이 라벨로 통일한다.
2. **질문형 H2 70% 이상** — 검색자가 실제 치는 질문 문구 그대로.
3. **각 H2 직후 40~75단어 직답(Q-A-E)** — 질문 → 자기완결 직답 → 근거·경험담. 산문 나열된 비교·수치는 **표로 전환**.
4. **`## 출처` 섹션 — 조건부다.**
   - ✅ **단다**: 대회·이벤트·법·세금·통계처럼 **공식 1차 출처가 실재하는 글** → URL + **확인일** 명시
   - ❌ **안 단다**: 전략·개념 설명처럼 **출처가 애매한 정보제공 글**. 억지로 출처를 만들지 말 것
   - 전략 글에서 근거를 밝히고 싶으면 출처 섹션 대신 **본문에서** "어림값이다"·"직접 검산했다"를 밝히면 된다
5. **FAQ 스키마** — `**Q. 질문**` + **빈 줄** + `A. 답변`. 감사는 **빌드 산출물**(`.next/server/app/blog/*.html`의 `"@type":"Question"` 수)로. 소스 raw 카운트는 CRLF→LF 정규화 탓에 틀린다.
6. **배치 순서** — 히어로 → 도입부 → `:::stripe` → **바로 답** → H2들 → `:::readnext` → FAQ → (출처) → 마무리
7. **결손 복구** — 필라 역링크 · 클러스터 형제 글과의 내부 일관성(같은 수치·용어) · 태그 카니발 · 축어 중복
8. **메타·이미지** — `updated` 오늘 / seoTitle ~32자 / desc ~95자 / `emoji` 공백 금지 / **이미지 맥락·alt 일치 육안 확인**(§14-4, §9-1)
9. **★기계 게이트 먼저, 사람은 그다음** — 편집한 글마다 `npm run audit:hard -- --slug=<slug>` 를 돌려 🔴 0건을 만든다.
   이 스크립트가 §13 핸드 검산(7장→베스트5 계산)·메타 길이·질문형 H2·FAQ 스키마·깨진 링크/301·
   백틱·축어 중복·형제 글 표 교차 대조를 **대신 본다. 손으로 다시 세지 마라.**
   - 게이트 자체 검증: `npm run audit:hard:selftest` (2026-08-06 기준 64/64, 2026-06-23 실제 사고를 잡는지 확인)
   - `--slug` 모드도 **소속 클러스터 형제를 자동으로 끌어와** 표 교차 대조를 한다(2026-08-01 수정).
     출력의 `대상: <slug> ↔ [클러스터] 형제 N편` 줄이 안 보이면 그 글이 `CLUSTERS` 정의에 없는 것이다
   - ⚠ **못 잡는 것 = D유형(전략적 유해 조언)·F유형(사실 오류)** → 여기에 사람의 시간을 쓴다
   - ⚠ 출력 맨 아래 **커버리지**를 반드시 읽어라. "시나리오를 못 잡은 글"의 0건은 **검증이 아니라 미검사**다
   - 왜 만들었나: 같은 방식의 통독은 몇 번을 반복해도 검출률이 오르지 않는다.
     **읽어서 통과시킬 수 있는 검사는 그럴듯하고 틀린 글이 반드시 통과한다.**
10. **적대적 검수는 필수** — Fable5 페르소나 병렬. ★**검산형과 SEO형을 반드시 함께** 돌린다(검산 에이전트가 놓친 판정 오류를 SEO 에이전트가 잡은 실례가 있다). **검수자도 틀린다** — 1차 출처가 심판.
10. **백틱 금지**(§12-A) — 편집 후 `npm run build` 확인.

## 17. SEO 카피 핵심 (제목·설명 빠른 참조)

> 상세: `.cursorrules` 및 `docs/SEO_COPY_GUIDELINES.md`. 핵심만 재정리.

- **공식**: `seoTitle: "[호기심·자극 훅] — [핵심 키워드 2~3개]"` / `desc: "[공감 한 문장]. [무엇을 알려주는지 + 키워드 + N분]"`
- 좋은 예: `"매판마다 칩이 빠지는 이유 — 홀덤 블라인드 뜻과 SB·BB 차이"`
- 금지: "OO 뜻 정리", "OO 완벽 정리", "총정리" 같은 정보형/흔한 마무리
- CTR 잘 나오는 호기심형 제목을 **정보형으로 단독 교체 금지** — 훅은 살리고 키워드만 보강
- 영어 포스트: 포스팅 전 구글 SERP Top10 + PAA(People Also Ask) 조사 → 검색자가 실제로 치는 표현을 H2/FAQ에 그대로 사용 (롱테일 6~8개를 한 글에 클러스터링)
- 다국어: 직역 금지, 포커 용어(ICM·bubble·bankroll 등)는 현지 검색 관습 우선, slug는 전 언어 동일(hreflang)
