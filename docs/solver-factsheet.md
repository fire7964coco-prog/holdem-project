## 1. 아키텍처

- 엔진 = 오픈소스 **wasm-postflop 포크**(Rust→WebAssembly, AGPL-3.0). 엔진 크레이트 `solver/rust/postflop-solver`.
- **계산은 유저 기기(브라우저)** 에서 돈다. 서버 연산 없음. 멀티스레드 wasm(COOP/COEP) · Safari 등은 단일 스레드 폴백.
- 배포 = Vercel 정적 prebuilt · `solver.holdemmaster.com` **noindex**(검색 유입은 본체 `/solver` 랜딩).
- 사전 계산 데이터 = 교육 예제 13개 결과 JSON(`solver/public/preset-results/` · 약 0.6MB) + 트레이너 33노드. 같은 wasm 엔진으로 추출 · 목표 exploitability 0.5%.
- TexasSolver = 독립 엔진 대조용(E3, 3스팟 통과)뿐. DesktopPostflop = 로컬 참고용.

## 3. 새 스팟을 계산할 수 있는가 — **있다**

- **유저 측**: 아무 HU 포스트플랍 스팟을 기기에서 푼다(레인지·보드·팟·스택·벳 사이즈·목표 오차 기본 0.3%). 메모리 상한 약 3.9GB(초과 시 16비트 모드). 넓은 레인지·레인보우 플랍은 초과 가능.
- **운영 측 사전 계산 파이프라인**(09-28 신설 · `참고자료/사전계산_도구_2026-09-28/`): 네이티브 Rust `precompute`(같은 엔진).
  - 1호 상황 `srp-btn-bb`: 팟 5.5bb · 스택 97.5bb · 플랍 벳 33%·75% · 턴/리버 60% · 레이즈 60% · 레이크 0 · 목표 1% · 최대 1000회 · 레인지 = 앱 프리플랍 차트 BTN RFI / BB 콜.
  - 무늬 동형 묶음 **1,755개 플랍 전부** · 플랍 단계 전략 + 액션별 EV만 저장(`HMR1` .bin). 턴·리버는 저장 안 함.
  - 사장님 서버(i7-14700K, 14스레드) · 상황 1개 약 175MB(압축 전).
  - **진행 상황(09-29)**: 1호 `srp-btn-bb` **완료**(09-29 14:36 · 1,755개 · 177MB · 전건 오차 1% 이하 · 플랍당 평균 46.9초 실측) · 위치 `참고자료/사전계산_결과/srp-btn-bb/`. 2~5호 `srp-sb-bb`→`co`→`hj`→`utg` 계산 중 · 10-02 전후 예상.
  - 형식 `HMR1`(정본 `참고자료/사전계산_도구_2026-09-28/precompute2/src/main.rs:177-240`) · 🔴 평균은 **가중 두 겹**(플랍별 `flopWeight` · 핸드별 도달 비중) — 그래서 **집계는 솔버가 만들어 준다**(S-027 제안). 본체가 직접 읽으면 두 겹을 지킨다.
  - 정밀도 실측: 1% ≈ 161초 · 0.3% ≈ 374초/플랍. 복기용 하한 = 1%.
  - 서빙 = Cloudflare 보관함(사장님 ○ 09-29 · 주소 미정). 3벳 팟 등은 아직 없음.
- ▶ **본체 활용**: 1,755 플랍 × 액션 빈도·EV = «보드 유형별 C벳 빈도» 같은 **본체 데이터 표의 원천**이 될 수 있다(방향 논의 2026-09-28). 쓰기 전 수치 인용 규칙은 §5·§13.
