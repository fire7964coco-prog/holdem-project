## 2. 토큰 — 만들 필요 없다, 이미 있다

`app/globals.css`에 Tailwind v4 방식으로 **라이트·다크 두 벌**이 이미 있고,
값이 HSL 3요소로 쪼개져 있다:

```
--primary:    43 65% 44%     ← 골드
--background: 37 33% 93%     ← 크림
--foreground: 152 45% 8%     ← 딥그린
```

맨 앞 숫자가 색상(hue)이라 **43을 다른 값으로 바꾸면 골드 계열 전체가 통째로 돈다.**
톤 실험에 이보다 좋은 구조가 없다.

🔴 **단, §1-B의 1,322곳이 이 토큰을 안 탄다.** 톤을 바꾸면 **그 자리들만 옛 톤으로 남는다.**
「바꿨는데 뭔가 안 맞는다」의 정체가 이것이다. → 할 일은 「토큰 만들기」가 아니라 **「토큰을 안 타는 자리 회수하기」**.

## 4. 레이아웃은 프롬프트로 푸는 문제가 아니다

**「단순하고 직관적으로 만들어줘」는 작동하지 않는다.** AI는 무엇을 뺄지 모르기 때문에,
빼는 대신 예쁘게 재배열한다. 조잡함이 **정돈된 조잡함**으로 바뀔 뿐이다.

조잡함은 디자인 문제가 아니라 **결정 문제**다 — 무엇을 뺄지 정하는 일이고 그건 사장님만 할 수 있다.
AI가 할 수 있는 건 **결정을 위한 재료를 정확히 차려주는 것**까지다.

### 4-A. 순서: 인벤토리 → 판정 → 그다음에 디자인

§1이 그 인벤토리다. 같은 스크립트를 다른 페이지(홈·허브·다국어)에도 돌리면 된다.

### 4-B. 실제로 쓸 프롬프트 골격

```
[맥락] 텍스트 포스팅 사이트다. 71편, 모바일 유입 68%, 한 글이 모바일 24화면.
      독자 목적은 "질문에 답을 얻는 것" 하나다. 커머스·대시보드가 아니다.

[현황] 이 화면에 있는 요소 전부다. (인벤토리 붙여넣기 — 크기와 역할 포함)

[요청] 디자인하지 마라. 먼저 판정만 해라.
      독자를 세 구간으로 나눠라 — ①읽기 전 ②읽는 중 ③다 읽은 후.
      각 요소를 구간에 배정하고,
      "이게 없으면 독자가 무엇을 못 하나"를 한 줄로 답해라.
      답이 안 나오는 요소를 따로 모아라.

[제약] 새 웹폰트 금지. 다크 배경 금지(크림 라이트가 우리 차별점).
      기존 URL·slug·라우트 변경 금지.
```

핵심 셋:
- **「디자인하지 마라, 판정만 해라」** — 안 쓰면 AI는 무조건 예쁜 걸 만들어 온다.
- **「이게 없으면 독자가 뭘 못 하나」** — 답이 안 나오는 게 뺄 것이다. 「있으면 좋다」는 답이 아니다.
- **읽기 전 / 읽는 중 / 다 읽은 후** — 조잡함은 대개 **「읽는 중」 구간에 조연이 침투**해서 생긴다.

### 4-C. 레퍼런스(Mobbin·핀터레스트)는 판정 **다음**이다

- **Mobbin** = 실제 출시된 앱·웹의 진짜 화면 = **작동하는 패턴**. 우리 같은 텍스트 사이트엔 이쪽.
- **핀터레스트** = 무드보드. 상당수가 드리블·비핸스 컨셉샷이라 **실제로는 안 굴러가는 목업**. 색·무드용으로만.

고를 때 우리 필터 넷:
1. **텍스트 읽는 사이트**를 봐라(블로그·뉴스·문서). 커머스·SaaS 대시보드는 푸는 문제가 다르다.
2. **긴 스크롤 화면**을 봐라 — 우리 최대 관문이 블로그 상세다.
3. **다크 테마 레퍼런스를 피하라** — AI 티 함정으로 되돌아간다. 크림 라이트가 이미 차별점이다.
4. **폰트가 개성인 레퍼런스를 피하라** — 새 웹폰트를 못 들인다(@font-face 438개 = FCP의 1/3 사고).

🔴 **저작권**: 레퍼런스 이미지를 그대로 넣고 「이렇게 만들어줘」 금지.
**「이 이미지를 분석해서 텍스트 프롬프트로 만들어줘」 → 그 프롬프트로만 작업.**
★ **3~5개를 모아 공통점을 뽑아라.** 하나면 복제가 되고 여럿이면 추상화가 된다.

## 5. 연동 — 무엇을 붙이면 좋은가

### 5-A. 세 시스템은 서로 안 통한다 (2026-08-17 실측)

| 층 | 사는 곳 | 현재 | 누가 쓰나 |
|---|---|---|---|
| **claude.ai 커넥터** | 계정(클라우드) | **GitHub만** | claude.ai 채팅 + **클로드 디자인** |
| **Claude Code MCP** | 이 PC | `.mcp.json`→playwright · `~/.claude.json`→rakko | **클로드 코드만** |
| **Claude Code 플러그인** | `~/.claude/plugins/` | vercel · exa · context7 · firecrawl · chrome-devtools | **클로드 코드만** |

**클로드 코드의 vercel·rakko·exa는 클로드 디자인에서 못 쓴다. 반대도 마찬가지다.**

### 5-B. 붙이면 값을 할 것

| 우선 | 무엇 | 어디에 | 왜 |
|---|---|---|---|
| ★★★ | **`/design-sync`** | 커넥터 아님 — **클로드 코드 기능** | 우리 디자인 시스템을 클로드 디자인에 올린다. 공식 문구: *"so Claude can build with your real components"*. 안 올리면 시안이 클로드 기본 취향(다크·박스·색선 = AI 티)으로 나온다. **이 세션에서 `DesignSync` 툴이 실제로 로드되는 것을 확인했다** |
| ★★ | **GitHub 커넥터** | claude.ai (**이미 연결됨**) | 클로드 디자인이 레포에서 디자인 시스템을 읽는 경로. 이미 돼 있으니 추가 작업 없음 |
| ★ | **Higgsfield** | claude.ai 커넥터 | **실사 이미지가 필요할 때만.** 🔴 Higgsfield 크레딧이 차감된다. §9 규격(1200×675·webp·≤60KB·워터마크 후합성)은 **우리 파이프라인이 처리해야 한다** — 생성기가 안 해준다 |

### 5-C. 붙일 필요 없는 것 (영상에 나왔지만 우리와 안 맞음)

- **Magnific**(업스케일) — 우리는 ≤60KB가 목표다. **방향이 반대다.**
- **Figma** — 우리는 Figma를 안 쓴다.
- **Notion·Slack·Gmail·Calendar·Drive** — 우리 워크플로에 없다.

### 5-D. 방향 구분 (헷갈리기 쉬움)

- **`/design-sync` = 코드 → 디자인 (올리기)**
- **「클로드 코드로 보내기」 = 디자인 → 코드 (내리기)**

**대체재가 아니라 왕복의 양 끝이다.** 올리기 없이 내리기만 하면 우리 사이트와 무관한 시안이 나온다.

🪶 **단 톤을 바꾸려는 지금은 뉘앙스가 있다** — 현재 토큰을 그대로 올리면 현재 톤에 갇힌다.
→ **구조는 올리고(컴포넌트 종류·간격·스케일), 색은 「이 구조 유지하고 톤만 이렇게」로 따로 지시.**
